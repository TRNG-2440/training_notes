3. What is DAG design?

DAG design is the process of converting a business workflow into tasks, dependencies, schedules, retries, parameters and operational controls.

4.4 TaskFlow dependency inference

@task
def extract():
    return {"rows": 100}

@task
def transform(metadata):
    return metadata["rows"]

result = extract()
transform(result)

Because the output of extract() is supplied to transform(), Airflow automatically understands the dependency.

5. Dynamic DAG generation

Dynamic DAG generation means Python code creates DAG objects or tasks from a list, dictionary, environment variable or generated configuration during DAG parsing.

Configuration list
→
Python loop / factory
→
sales_chennai

sales_bengaluru

sales_hyderabad

Why use it?

  • Avoid copying nearly identical DAG files.
  • Apply the same standards to many customers, regions, tables or data sources.
  • Add a new workflow by changing configuration instead of duplicating code.
  • Reduce maintenance and inconsistency.
Do not confuse this with Dynamic Task Mapping. Dynamic DAG generation creates the graph while Airflow parses the DAG file. Dynamic Task Mapping expands task instances at run time using upstream results.

8. Real-world scenario

A retail company receives sales data for three cities. Every city follows the same process:

Start
→
Extract city sales
→
Filter by minimum amount
→
Calculate summary
→
Publish report

We will implement two alternatives:

  1. Dynamic DAG factory: creates three DAGs—one per city.
  2. Parameterized DAG: creates one DAG whose city and amount threshold are entered during triggering.

11. Example 1 — Basic DAG and dependencies

Create $AIRFLOW_HOME/dags/01_basic_dependency_dag.py.

from datetime import datetime
from airflow.sdk import dag, task


@dag(
    dag_id="basic_sales_dependency_demo",
    schedule=None,
    start_date=datetime(2026, 1, 1),
    catchup=False,
    tags=["training", "dependencies"],
)
def basic_sales_dependency_demo():

    @task
    def extract():
        print("Extracting sales")
        return [500, 1200, 2000, 300]

    @task
    def validate(values):
        if not values:
            raise ValueError("No sales records")
        print(f"Validated {len(values)} records")

    @task
    def transform(values):
        result = [value for value in values if value >= 1000]
        print(f"Filtered values: {result}")
        return result

    @task
    def load(values):
        print(f"Loading {len(values)} high-value sales")

    sales = extract()
    validation = validate(sales)
    transformed = transform(sales)

    # Fan-out: validate and transform both depend on extract.
    # Fan-in: load waits for both validation and transform.
    validation >> transformed
    load(transformed)

12. Example 2 — Dynamic DAG factory

Create $AIRFLOW_HOME/dags/02_dynamic_city_dags.py.

from datetime import datetime
from airflow.sdk import dag, task


CITY_CONFIGS = [
    {"city": "chennai", "min_amount": 1000},
    {"city": "bengaluru", "min_amount": 1500},
    {"city": "hyderabad", "min_amount": 1200},
]


def create_city_sales_dag(city: str, min_amount: int):

    @dag(
        dag_id=f"sales_etl_{city}",
        schedule=None,
        start_date=datetime(2026, 1, 1),
        catchup=False,
        tags=["dynamic-dag", city],
        description=f"Sales ETL generated for {city}",
    )
    def city_sales_dag():

        @task
        def extract() -> list[dict]:
            sample_data = {
                "chennai": [
                    {"order_id": 1, "amount": 800},
                    {"order_id": 2, "amount": 1800},
                ],
                "bengaluru": [
                    {"order_id": 3, "amount": 1600},
                    {"order_id": 4, "amount": 900},
                ],
                "hyderabad": [
                    {"order_id": 5, "amount": 1300},
                    {"order_id": 6, "amount": 700},
                ],
            }
            rows = sample_data[city]
            print(f"Extracted {rows}")
            return rows

        @task
        def filter_high_value(rows: list[dict]) -> list[dict]:
            selected = [
                row for row in rows
                if row["amount"] >= min_amount
            ]
            print(f"{city}: threshold={min_amount}, selected={selected}")
            return selected

        @task
        def summarize(rows: list[dict]) -> dict:
            summary = {
                "city": city,
                "order_count": len(rows),
                "total_amount": sum(row["amount"] for row in rows),
            }
            print(summary)
            return summary

        @task
        def publish(summary: dict):
            print(f"Published report: {summary}")

        rows = extract()
        filtered = filter_high_value(rows)
        summary = summarize(filtered)
        publish(summary)

    return city_sales_dag()


# Airflow imports this file. The loop creates three DAG objects.
for config in CITY_CONFIGS:
    dag_object = create_city_sales_dag(
        city=config["city"],
        min_amount=config["min_amount"],
    )

    # Register each generated DAG in the module's global namespace.
    globals()[dag_object.dag_id] = dag_object

How the file works

CITY_CONFIGS stores the differences between cities.
create_city_sales_dag() is a reusable DAG factory.
The loop calls the factory once per configuration entry.
globals() exposes each generated DAG object to Airflow.
The UI displays sales_etl_chennai, sales_etl_bengaluru and sales_etl_hyderabad.
Add another city by adding one dictionary to CITY_CONFIGS. You do not need to copy the complete DAG.

13. Example 3 — Parameterized DAG

Create $AIRFLOW_HOME/dags/03_parameterized_sales_dag.py.

from datetime import datetime
from airflow.sdk import dag, task
from airflow.sdk.definitions.param import Param


@dag(
    dag_id="parameterized_sales_etl",
    schedule=None,
    start_date=datetime(2026, 1, 1),
    catchup=False,
    tags=["parameters", "training"],
    params={
        "city": Param(
            default="chennai",
            type="string",
            enum=["chennai", "bengaluru", "hyderabad"],
            title="City",
        ),
        "min_amount": Param(
            default=1000,
            type="integer",
            minimum=0,
            title="Minimum order amount",
        ),
        "processing_date": Param(
            default="2026-07-31",
            type="string",
            format="date",
            title="Processing date",
        ),
    },
)
def parameterized_sales_etl():

    @task
    def extract(**context) -> list[dict]:
        city = context["params"]["city"]
        processing_date = context["params"]["processing_date"]

        sample_rows = [
            {"order_id": 101, "city": city, "amount": 700},
            {"order_id": 102, "city": city, "amount": 1400},
            {"order_id": 103, "city": city, "amount": 2500},
        ]

        print(f"Date={processing_date}; city={city}")
        return sample_rows

    @task
    def transform(rows: list[dict], **context) -> list[dict]:
        min_amount = context["params"]["min_amount"]
        result = [
            row for row in rows
            if row["amount"] >= min_amount
        ]
        print(f"Threshold={min_amount}; output={result}")
        return result

    @task
    def publish(rows: list[dict], **context):
        city = context["params"]["city"]
        total = sum(row["amount"] for row in rows)
        print({
            "city": city,
            "selected_orders": len(rows),
            "total_amount": total,
        })

    rows = extract()
    cleaned = transform(rows)
    publish(cleaned)


parameterized_sales_etl()

  "city": "chennai",
  "min_amount": 1200,
  "processing_date": "2026-07-31"
}

Confirm that the files are present
ls -l "$AIRFLOW_HOME/dags"
Check DAG parsing
airflow dags list
Open the UI

In your Windows browser, open http://localhost:8080.

Sign in

Use the username shown by airflow standalone. For Airflow 3.x local standalone mode, the generated password can be found in:

cat "$AIRFLOW_HOME/simple_auth_manager_passwords.json.generated"
Locate the DAG

Search for parameterized_sales_etl or one of the generated city DAG IDs.

Trigger a generated DAG

Open sales_etl_chennai, then click the Trigger button.

Trigger the parameterized DAG

Open parameterized_sales_etl, click Trigger, enter the city, threshold and date, then confirm.

View execution

Use the Grid view for task states, Graph view for dependencies, and task logs to inspect printed output.

Useful CLI commands

# List DAGs
airflow dags list

# Show import errors
airflow dags list-import-errors

# Test one task without creating a normal scheduled run
airflow tasks test parameterized_sales_etl extract 2026-07-31

# Trigger a DAG with parameters
airflow dags trigger parameterized_sales_etl \
  --conf '{"city":"chennai","min_amount":1200,"processing_date":"2026-07-31"}'

17. Best practices

  • Keep DAG IDs and task IDs stable between parses.
  • Generate tasks from consistently sorted configuration.
  • Avoid database calls, network requests and heavy computation at module import time.
  • Keep large datasets in files, object storage, databases or warehouses—not in XCom.
  • Use parameters for run-specific values and configuration files/environment variables for deployment-specific values.
  • Make tasks idempotent: retrying the same task should not corrupt data.
  • Use a factory function rather than copying complete DAG files.
  • Add validation to parameters using type, enum, minimum and format rules.
  • Test DAG files as production code.

18. Interview questions and answers

1. Why must a DAG be acyclic?

A cycle would create an impossible circular dependency in which tasks wait on each other forever.

2. What does A >> B mean?

Task A is upstream and task B is downstream. B waits for A according to its trigger rule.

3. Dynamic DAG or parameter?

Use dynamic generation when you need separate DAGs or structures; use parameters when one structure should run with different values.

4. What is DAG parsing?

Airflow imports the Python file and discovers the DAG objects defined by it.

5. Why avoid external API calls at parse time?

DAG files are parsed repeatedly, so slow calls can delay discovery and overload services.

6. Dynamic DAG generation vs task mapping?

Generation occurs while parsing; task mapping expands task instances during a DAG Run.

7. What is fan-out?

One upstream task enables several downstream tasks to run, often in parallel.

8. What is fan-in?

Several upstream branches converge into one downstream task.

9. What makes a task idempotent?

Running it repeatedly with the same input produces the same safe result.

10. Why use Param validation?

It prevents invalid run configuration and gives users a clearer trigger form.

11. Where do logs appear?

Open the DAG Run, select a task instance and choose its log view.

12. What is catchup?

It controls whether Airflow creates historical scheduled runs between the start date and current scheduling interval.

13. Why use schedule=None in labs?

It avoids automatic runs and lets the learner trigger each example manually.

14. Can one Python file define several DAGs?

Yes. Airflow can discover multiple DAG objects from one module.

15. Why sort dynamic configuration?

Stable ordering keeps the generated task/DAG structure consistent in the UI and metadata.
