1. What the referenced video demonstrates

The referenced video is titled “Google Cloud Dataflow Explained | Create Your First Data Pipeline (GCS to BigQuery)”. Its practical goal is a batch ETL pipeline in which a text/CSV file is stored in Cloud Storage, transformed by Dataflow and inserted into a BigQuery table.

Portal-version note: Google Cloud Console labels and template screens can change. These notes preserve the same workflow while also documenting the currently required configuration and common permission fixes.

2. What is Google Cloud Dataflow?

Dataflow is Google Cloud’s managed execution service for Apache Beam pipelines. A pipeline normally reads from a source, applies one or more transforms and writes to a destination. The same service supports batch and streaming workloads.

Source
Cloud Storage CSV/text file
Transform
Parse each line and convert it to JSON
Sink
BigQuery table
Runner
Google Cloud Dataflow

Important schema wrapper

{
  "BigQuery Schema": [
    {"name":"order_id","type":"INTEGER","mode":"NULLABLE"},
    {"name":"customer_name","type":"STRING","mode":"NULLABLE"}
  ]
}

The classic template expects the schema file in its documented wrapper format. Supplying only a plain field array can produce schema-reading errors.

8. IAM and service-account configuration

For a simple lab, the default Compute Engine service account may be used as the Dataflow worker service account:

PROJECT_NUMBER-compute@developer.gserviceaccount.com

Recommended worker roles for the lab

ScopeRoleReason
ProjectDataflow WorkerAllows worker instances to perform Dataflow work.
Input/staging bucketStorage Object AdminRead source files and create staging/temp objects.
BigQuery datasetBigQuery Data EditorCreate/write destination table data.
ProjectBigQuery Job UserRun BigQuery jobs.
PROJECT_NUMBER=$(gcloud projects describe YOUR_PROJECT_ID \
  --format="value(projectNumber)")

WORKER_SA="${PROJECT_NUMBER}-compute@developer.gserviceaccount.com"

gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
  --member="serviceAccount:${WORKER_SA}" \
  --role="roles/dataflow.worker"

gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
  --member="serviceAccount:${WORKER_SA}" \
  --role="roles/bigquery.jobUser"
In production, use a dedicated least-privilege service account instead of broadly granting roles to the default Compute Engine service account.

14. Monitor the Dataflow job

After submission, Dataflow opens the job-details screen.

Dataflow job graph — gcs-to-bigquery-orders
✓ Read from Cloud Storage
↓
✓ Apply JavaScript UDF
↓
✓ Convert / validate records
↓
✓ Write to BigQuery

Review these areas:

  • Job graph: each pipeline transform and its status.
  • Execution details: worker progress and stage information.
  • Job metrics: elements processed, throughput and resource usage.
  • Logs: JavaScript errors, schema mismatch, IAM and file-access errors.

The final state should be Succeeded. A batch job stops automatically after processing all input.

15. Validate data in BigQuery

Open BigQuery → sales → customer_orders → Preview, then run:

SELECT *
FROM `YOUR_PROJECT_ID.sales.customer_orders`
ORDER BY order_id;

Validation queries

-- Number of loaded records
SELECT COUNT(*) AS row_count
FROM `YOUR_PROJECT_ID.sales.customer_orders`;

-- Revenue by state
SELECT state, ROUND(SUM(amount), 2) AS total_revenue
FROM `YOUR_PROJECT_ID.sales.customer_orders`
GROUP BY state
ORDER BY total_revenue DESC;

-- Category summary
SELECT category,
       COUNT(*) AS order_count,
       ROUND(AVG(amount), 2) AS average_amount
FROM `YOUR_PROJECT_ID.sales.customer_orders`
GROUP BY category
ORDER BY order_count DESC;

Expected sample row count: 10.

16. Command-line equivalent of the template job

gcloud dataflow jobs run gcs-to-bigquery-orders \
  --gcs-location="gs://dataflow-templates-us-central1/latest/GCS_Text_to_BigQuery" \
  --region="us-central1" \
  --staging-location="gs://YOUR_PROJECT_ID-dataflow-lab/staging" \
  --service-account-email="WORKER_SERVICE_ACCOUNT_EMAIL" \
  --parameters="\
javascriptTextTransformFunctionName=transform,\
JSONPath=gs://YOUR_PROJECT_ID-dataflow-lab/config/schema.json,\
javascriptTextTransformGcsPath=gs://YOUR_PROJECT_ID-dataflow-lab/config/transform.js,\
inputFilePattern=gs://YOUR_PROJECT_ID-dataflow-lab/input/customer_orders.csv,\
outputTable=YOUR_PROJECT_ID:sales.customer_orders,\
bigQueryLoadingTemporaryDirectory=gs://YOUR_PROJECT_ID-dataflow-lab/temp"
Template parameter names and regional template paths can evolve. Confirm the parameter list displayed by the current template in your project before automating a production deployment.

17. Troubleshooting guide

Error/symptomCauseCorrection
Permission denied on GCSWorker service account cannot read input or write temp/staging objects.Grant bucket-level object permissions to the actual worker identity.
Permission denied on BigQueryMissing dataset write role or project job role.Grant BigQuery Data Editor on the dataset and BigQuery Job User on the project.
UDF function not foundFunction field does not match JS function name.Use exactly transform.
Expected 7 columnsMalformed CSV row or embedded comma.Clean the file or use a proper CSV parser in a custom Apache Beam pipeline.
Invalid dateDate does not match BigQuery DATE format.Use YYYY-MM-DD.
Location mismatchGCS, BigQuery and processing locations are incompatible.Create all lab resources with a compatible regional strategy.
Table already exists / write errorTemplate write disposition conflicts with existing table.Delete the test table, use a new name or configure append/truncate when supported.
Header inserted as a rowUDF did not filter the header.Return null when the first column equals order_id.
Job stays queuedAPI, quota, worker provisioning or organisation policy issue.Review job messages, quotas, VPC rules and Compute Engine API status.

18. Cost control and cleanup

Dataflow can create worker resources and incur charges. The sample is intentionally small, but cleanup is still necessary.

# Delete the destination table
bq rm -f -t YOUR_PROJECT_ID:sales.customer_orders

# Delete the dataset and any remaining tables
bq rm -r -f -d YOUR_PROJECT_ID:sales

# Delete the bucket and all objects
gcloud storage rm --recursive gs://YOUR_PROJECT_ID-dataflow-lab
Never delete a shared production bucket or dataset. Confirm the project ID and resource names before running cleanup commands.

19. Interview questions and answers

1. What is Dataflow?
A managed Google Cloud service for executing Apache Beam batch and streaming pipelines.
2. Why is a temp bucket required?
Workers use it for temporary data and intermediate pipeline artifacts.
3. Why use a UDF?
The template receives text lines; the UDF converts each line into JSON matching the BigQuery schema.
4. What is a batch job?
A finite pipeline that processes bounded input and stops after completion.
5. What is a PTransform?
An Apache Beam operation that transforms one or more PCollections.
6. Why must locations match?
Cloud services impose data-location compatibility rules and cross-region limitations.
7. Who accesses the input file?
The Dataflow worker service account, not merely the interactive console user.
8. How are failures investigated?
Use the Dataflow job graph, execution details, job messages and Cloud Logging.
9. Template vs custom Beam?
A template is prebuilt and parameterised; custom Beam gives complete transform control.
10. Why make consumers/transforms idempotent?
Retries can repeat work, so duplicate side effects must be prevented.
