1. Learning outcomes

After completing this tutorial, you will be able to:

  • Explain why credentials should not be hard-coded in a DAG.
  • Create and test Airflow Connections using the UI, CLI, and environment variables.
  • Use Hooks in Python tasks to communicate with external systems.
  • Read and write SQL Server data from a DAG.
  • Understand the practical limitation of Windows Integrated Authentication when Airflow runs in WSL2 or Linux containers.
  • Download a CSV from Google Cloud Storage, process it, and upload the result.

Memory aid: A Connection stores the address and authentication details. A Hook is Python code that uses those details to communicate with the system.

3. What is an Airflow Connection?

An Airflow Connection is a named configuration record for an external service. Common fields include connection type, host, schema/database, login, password, port, and an Extra JSON field.

FieldMeaningSQL Server exampleGCS example
Connection IDUnique name used in DAG codesqlserver_labgoogle_cloud_default
Connection TypeProvider/protocolMicrosoft SQL Server or ODBCGoogle Cloud
HostServer name/IPhost.docker.internal, IP, or SQL hostUsually blank
SchemaDatabase or logical schemaAirflowLabDBUsually blank
Login/PasswordCredentialsSQL login or service account setupUsually service-account JSON/ADC
ExtraProvider-specific optionsDriver, encryption, trust optionsProject ID, key path/JSON, scopes
Important: The DAG refers to the Connection ID—not the password. Airflow resolves the actual record at runtime.

Where Connections can be stored

  • Airflow metadata database through the web UI or CLI.
  • Environment variables such as AIRFLOW_CONN_SQLSERVER_LAB.
  • A Secrets Backend such as HashiCorp Vault, AWS Secrets Manager, Google Secret Manager, or Azure Key Vault.

4. What is an Airflow Hook?

A Hook is a reusable Python interface for communicating with an external platform. It normally retrieves an Airflow Connection by its ID, creates a client/connection, and provides convenient methods.

HookExternal serviceTypical methods
MsSqlHookMicrosoft SQL Serverget_conn(), get_records(), run()
OdbcHookODBC data sourcesget_conn(), get_df(), run()
GCSHookGoogle Cloud Storagedownload(), download_as_bytes(), upload(), list()
HttpHookREST APIsrun(), get_conn()
from airflow.providers.microsoft.mssql.hooks.mssql import MsSqlHook

hook = MsSqlHook(mssql_conn_id="sqlserver_lab")
rows = hook.get_records("SELECT TOP 5 * FROM dbo.sales")

5. Connection vs Hook vs Operator

ConceptPurposeAnalogy
ConnectionStores configuration and credentialsSaved contact card
HookPython client used to communicatePhone used to call the contact
OperatorDefines a complete Airflow taskA scheduled activity such as “call customer”
Rule: Use an Operator when a ready-made task already does what you need. Use a Hook inside Python code when you need custom logic.

6. Creating Connections

Method A — Airflow UI

Open Airflow UI.
Go to Admin → Connections (in some Airflow 3 interfaces: Assets/Administration → Connections depending on deployment and permissions).
Click + or Add Connection.
Enter Connection ID, type, host, database/schema, credentials, port, and Extra JSON.
Save, then use that Connection ID in the DAG.

Method B — CLI

airflow connections add 'sqlserver_lab' \
  --conn-type 'mssql' \
  --conn-host '192.168.1.20' \
  --conn-schema 'AirflowLabDB' \
  --conn-login 'airflow_user' \
  --conn-password 'StrongPasswordHere' \
  --conn-port '1433'

Method C — environment variable

export AIRFLOW_CONN_SQLSERVER_LAB='mssql://airflow_user:password@192.168.1.20:1433/AirflowLabDB'
Do not commit credentials to Git. For production, prefer a secrets backend or environment-injected secret.

7. Simple Hook example: test a public HTTP API

This example demonstrates the pattern before introducing databases and cloud credentials.

Install provider

pip install apache-airflow-providers-http

Create connection

Connection ID: weather_api, type: HTTP, host: https://api.open-meteo.com.

DAG

from datetime import datetime
from airflow import DAG
from airflow.operators.python import PythonOperator
from airflow.providers.http.hooks.http import HttpHook


def read_weather():
    hook = HttpHook(method="GET", http_conn_id="weather_api")
    response = hook.run(
        endpoint="/v1/forecast",
        data={"latitude": 11.0168, "longitude": 76.9558,
              "current": "temperature_2m"},
    )
    print(response.json())

with DAG(
    dag_id="hook_http_demo",
    start_date=datetime(2025, 1, 1),
    schedule=None,
    catchup=False,
    tags=["connections", "hooks"],
) as dag:
    read_api = PythonOperator(task_id="read_weather", python_callable=read_weather)

8.5 DAG: read, aggregate, and write summary

from datetime import datetime
from airflow import DAG
from airflow.operators.python import PythonOperator
from airflow.providers.microsoft.mssql.hooks.mssql import MsSqlHook

CONN_ID = "sqlserver_lab"


def check_connection():
    hook = MsSqlHook(mssql_conn_id=CONN_ID)
    row = hook.get_first("SELECT DB_NAME(), SYSTEM_USER, GETDATE()")
    print(f"database={row[0]}, user={row[1]}, server_time={row[2]}")


def refresh_city_summary():
    hook = MsSqlHook(mssql_conn_id=CONN_ID)
    sql = """
    MERGE dbo.city_sales_summary AS target
    USING (
        SELECT city, SUM(amount) AS total_amount
        FROM dbo.sales_orders
        GROUP BY city
    ) AS source
    ON target.city = source.city
    WHEN MATCHED THEN
        UPDATE SET total_amount = source.total_amount,
                   refreshed_at = SYSDATETIME()
    WHEN NOT MATCHED THEN
        INSERT (city, total_amount, refreshed_at)
        VALUES (source.city, source.total_amount, SYSDATETIME());
    """
    hook.run(sql)


def print_summary():
    hook = MsSqlHook(mssql_conn_id=CONN_ID)
    rows = hook.get_records(
        "SELECT city, total_amount, refreshed_at "
        "FROM dbo.city_sales_summary ORDER BY total_amount DESC"
    )
    for row in rows:
        print(row)

with DAG(
    dag_id="sqlserver_sales_summary",
    start_date=datetime(2025, 1, 1),
    schedule=None,
    catchup=False,
    tags=["sqlserver", "hooks"],
) as dag:
    t1 = PythonOperator(task_id="check_connection", python_callable=check_connection)
    t2 = PythonOperator(task_id="refresh_city_summary", python_callable=refresh_city_summary)
    t3 = PythonOperator(task_id="print_summary", python_callable=print_summary)
    t1 >> t2 >> t3

9. Connecting to SQL Server with Windows Authentication

Critical distinction: Your SSMS screenshot shows that SSMS is using your Windows desktop identity. That authentication token is not automatically inherited by Airflow when Airflow runs inside WSL2 or a Linux Docker container.

When Integrated Authentication can work

  • The Airflow task process runs under a Windows account that SQL Server trusts, using a compatible ODBC driver; or
  • The Linux/WSL Airflow environment is configured for Active Directory/Kerberos and can obtain a valid ticket; or
  • A managed identity/domain service setup is available in an enterprise environment.

Official Airflow deployments are Linux-oriented; Windows users normally run Airflow through WSL2 or Linux containers. Therefore, SQL authentication is the easiest reliable choice for a local lab.

ODBC connection pattern for Integrated Authentication

Use this only when the Airflow worker environment genuinely supports the Windows/Kerberos identity.

Install packages

pip install apache-airflow-providers-odbc pyodbc

Also install Microsoft ODBC Driver 18 for SQL Server in the environment where the Airflow task executes.

from datetime import datetime
from airflow import DAG
from airflow.operators.python import PythonOperator
from airflow.providers.odbc.hooks.odbc import OdbcHook


def test_windows_auth():
    hook = OdbcHook(odbc_conn_id="sqlserver_windows_auth")
    with hook.get_conn() as conn:
        cursor = conn.cursor()
        cursor.execute("SELECT SYSTEM_USER, ORIGINAL_LOGIN(), DB_NAME()")
        print(cursor.fetchone())

with DAG(
    dag_id="sqlserver_windows_auth_test",
    start_date=datetime(2025, 1, 1),
    schedule=None,
    catchup=False,
) as dag:
    PythonOperator(task_id="test_windows_auth", python_callable=test_windows_auth)
Named instance note: SQLEXPRESS frequently uses a dynamic port. For Airflow, a fixed TCP port such as 1433 is easier. Enable TCP/IP in SQL Server Configuration Manager, assign a static port, restart SQL Server, and allow the port through Windows Firewall.

10.5 Complete DAG

from __future__ import annotations

import csv
import io
from collections import defaultdict
from datetime import datetime

from airflow import DAG
from airflow.operators.python import PythonOperator
from airflow.providers.google.cloud.hooks.gcs import GCSHook

GCP_CONN_ID = "google_cloud_default"
BUCKET = "airflow-training-bucket"   # change this
INPUT_OBJECT = "input/sales.csv"
OUTPUT_OBJECT = "output/city_sales_summary.csv"


def process_gcs_csv():
    hook = GCSHook(gcp_conn_id=GCP_CONN_ID)

    # 1. Download the object as bytes.
    raw_bytes = hook.download_as_bytes(
        bucket_name=BUCKET,
        object_name=INPUT_OBJECT,
    )
    text = raw_bytes.decode("utf-8-sig")

    # 2. Read and validate the CSV.
    reader = csv.DictReader(io.StringIO(text))
    required = {"city", "amount"}
    missing = required - set(reader.fieldnames or [])
    if missing:
        raise ValueError(f"Missing required columns: {sorted(missing)}")

    # 3. Filter and aggregate.
    totals = defaultdict(float)
    accepted_rows = 0
    for row_number, row in enumerate(reader, start=2):
        try:
            amount = float(row["amount"])
        except (TypeError, ValueError) as exc:
            raise ValueError(
                f"Invalid amount at CSV row {row_number}: {row.get('amount')}"
            ) from exc

        if amount >= 1000:
            totals[row["city"].strip()] += amount
            accepted_rows += 1

    # 4. Create output CSV in memory.
    output = io.StringIO()
    writer = csv.writer(output, lineterminator="\n")
    writer.writerow(["city", "total_amount"])
    for city, total in sorted(totals.items()):
        writer.writerow([city, f"{total:.2f}"])

    # 5. Upload processed data.
    hook.upload(
        bucket_name=BUCKET,
        object_name=OUTPUT_OBJECT,
        data=output.getvalue(),
        mime_type="text/csv",
    )

    print(f"Accepted rows: {accepted_rows}")
    print(f"Uploaded: gs://{BUCKET}/{OUTPUT_OBJECT}")


with DAG(
    dag_id="gcs_read_process_upload",
    start_date=datetime(2025, 1, 1),
    schedule=None,
    catchup=False,
    tags=["gcs", "hooks", "csv"],
) as dag:
    PythonOperator(
        task_id="process_gcs_csv",
        python_callable=process_gcs_csv,
    )

11. Security and design best practices

  • Never hard-code secrets in DAG Python files.
  • Give service accounts and SQL users only the permissions required by the task.
  • Use a Secrets Backend for production.
  • Rotate credentials and avoid long-lived service-account keys where workload identity is available.
  • Keep heavy business logic in tested Python modules, not a very large DAG file.
  • Make tasks idempotent. Re-running a DAG should not create duplicate results.
  • Set network timeouts, retries, and meaningful error messages.
  • Do not return large datasets through XCom; use storage/database objects and pass only references.

13. Interview questions and answers

1. Why use Airflow Connections?

They centralize external-system configuration and prevent credentials from being repeated in DAG code.

2. What is a Hook?

A provider-specific Python interface that creates a client or database connection and exposes reusable methods.

3. How does a Hook find credentials?

It receives a connection ID and asks Airflow to resolve the matching Connection from the configured secrets sources.

4. Connection vs Operator?

A Connection stores configuration. An Operator defines a task. An Operator may internally use a Hook.

5. What is the Extra field?

A JSON object for provider-specific values such as an ODBC driver, project ID, encryption flags, or key configuration.

6. Can Connections be stored outside the metadata database?

Yes. Environment variables and external Secrets Backends are supported.

7. Why avoid large results in XCom?

XCom is designed for small task metadata, not large datasets. Large data should remain in object storage or databases.

8. Why might localhost be wrong in Docker?

It points to the container itself, not the Windows host.

9. Why does SSMS Windows Authentication work while Airflow fails?

SSMS runs under the Windows user session. Airflow in Linux/WSL does not automatically possess that Windows access token.

10. What is GCSHook used for?

Listing, downloading, uploading, copying, deleting, and checking objects in Google Cloud Storage.

11. What is least privilege?

Granting only the minimum actions and resources needed for the workflow.

12. How do you make a database task idempotent?

Use deterministic keys and patterns such as MERGE/upsert, replace-partition, or delete-and-reload for a known scope.

13. What happens if a provider is missing?

The connection type and Hook imports may be unavailable, causing DAG import errors or missing UI options.

14. What is a sensor in the GCS workflow?

A task that waits until a condition is true, such as an object appearing in a bucket.

15. What is the safest credential method on cloud infrastructure?

Prefer workload identity/managed identity or short-lived credentials over downloaded long-lived key files.
