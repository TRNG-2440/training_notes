1. Learning Objectives

After completing this tutorial, you will be able to:

  • Explain why Airflow is not installed directly as a normal native Windows service.
  • Install WSL 2 and Docker Desktop correctly.
  • Download and start the official Apache Airflow Docker Compose learning stack.
  • Understand the purpose of every running container.
  • Create a DAG file and observe it in the Airflow UI.
  • Use Home, DAG List, Overview, Grid, Graph, Runs, Tasks, Code, Details, Logs, XCom, Assets, Connections, Variables, Pools, Providers, and Config pages.
  • Diagnose common Windows, WSL, Docker, port, memory, and DAG parsing problems.
Memory path: Windows hosts Docker Desktop → Docker runs Linux containers → the containers run Airflow services → your browser opens the Airflow UI.

2. Important: How Airflow Runs on Windows

Apache Airflow is designed for POSIX-compatible operating systems. It is not officially supported as a native Windows installation. On Windows, use one of these Linux-based approaches:

Recommended for this tutorial

Docker Desktop with WSL 2 backend. It is easier to reproduce, includes PostgreSQL and Redis, and closely follows the official Airflow Docker Compose guide.

Alternative

Install inside an Ubuntu WSL 2 distribution. This is useful for learning Linux administration, but you must manually manage Python, databases, services, and dependencies.

Do not use: pip install apache-airflow directly in ordinary Windows PowerShell or Command Prompt and expect a supported native Windows deployment.

3. Windows Airflow Setup Architecture

Why multiple containers?

ContainerPurposeWhat happens when unavailable?
airflow-api-serverServes the Airflow 3 UI and REST API.The browser cannot use the UI.
airflow-schedulerExamines schedules and queues runnable task instances.New scheduled tasks stop being queued.
airflow-dag-processorImports and parses DAG Python files.New or changed DAGs may not appear.
airflow-workerExecutes queued tasks.Tasks remain queued.
airflow-triggererHandles asynchronous triggers for deferrable tasks.Deferred tasks cannot resume correctly.
postgresStores Airflow metadata and task state.Most Airflow components cannot work.
redisCelery message broker between scheduler and worker.Queued work is not delivered to workers.
airflow-initRuns initialization and creates the learning user.Used once before normal startup.

12. Create a Sample DAG for the UI Walkthrough

Create this file:

C:\AirflowLab\dags\airflow_ui_demo.py
from __future__ import annotations

from datetime import timedelta

import pendulum
from airflow.sdk import dag, task


@dag(
    dag_id="airflow_ui_demo",
    schedule=None,
    start_date=pendulum.datetime(2026, 1, 1, tz="UTC"),
    catchup=False,
    tags=["training", "ui-demo"],
    default_args={
        "retries": 1,
        "retry_delay": timedelta(seconds=20),
    },
)
def airflow_ui_demo():

    @task
    def extract() -> list[dict]:
        records = [
            {"order_id": 101, "amount": 120.50},
            {"order_id": 102, "amount": 80.00},
            {"order_id": 103, "amount": 220.25},
        ]
        print(f"Extracted {len(records)} orders")
        return records

    @task
    def validate(records: list[dict]) -> dict:
        if not records:
            raise ValueError("No orders received")

        for record in records:
            if record["amount"] < 0:
                raise ValueError(
                    f"Negative amount for order {record['order_id']}"
                )

        result = {
            "records": records,
            "row_count": len(records),
            "quality_status": "PASS",
        }
        print(result)
        return result

    @task
    def transform(validation_result: dict) -> dict:
        total_amount = round(
            sum(
                record["amount"]
                for record in validation_result["records"]
            ),
            2,
        )
        summary = {
            "order_count": validation_result["row_count"],
            "total_amount": total_amount,
            "quality_status": validation_result["quality_status"],
        }
        print(summary)
        return summary

    @task
    def load(summary: dict) -> str:
        print(
            "Pretending to load the following summary "
            "into a warehouse:"
        )
        print(summary)
        return "warehouse.daily_order_summary"

    @task
    def publish_report(table_name: str) -> None:
        print(f"Dashboard can now read from {table_name}")

    extracted = extract()
    checked = validate(extracted)
    transformed = transform(checked)
    loaded_table = load(transformed)
    publish_report(loaded_table)


airflow_ui_demo()

Confirm DAG discovery

docker compose run --rm airflow-worker `
  airflow dags list | Select-String "airflow_ui_demo"

Check parsing errors

docker compose run --rm airflow-worker `
  airflow dags list-import-errors
What this DAG demonstrates: dependency flow, task states, logs, retries, XCom return values, task durations, code view, and run history.

17. Grid View: Main Operations Screen

Grid View is the most useful screen for monitoring task instances over time.

How to read the matrix

  • Each row is a task.
  • Each column is a DAG run.
  • Each cell is one task instance.
  • Hover for state, time, attempt, and duration details.
  • Click a cell to open logs, clear, mark state, or inspect metadata according to permission.

Common states

Success Failed Running / retry-related Queued / scheduled Skipped None / upstream blocked

Exact colors and appearance can vary by Airflow version and theme; rely on the displayed state name and tooltip.

Open a task cell or task instance row to inspect one task execution.

Rendered TemplatesFinal values of templated fields after macros and run context are applied.Verify SQL dates, file paths, commands, and parameters.

Log-reading method

  1. Start at the bottom and locate the final exception.
  2. Read the traceback upward to find your DAG function or operator call.
  3. Identify whether the failure is transient, data-related, permission-related, dependency-related, or code-related.
  4. Fix the root cause before clearing or retrying.
  5. Confirm the task is idempotent before rerun.

25. PowerShell Script to Set Up the Airflow Project

This script assumes that WSL 2 and Docker Desktop are already installed and Docker is running.

Create C:\AirflowLab\setup-airflow.ps1:

[CmdletBinding()]
param(
    [string]$ProjectPath = "C:\AirflowLab",
    [string]$AirflowVersion = "3.3.0"
)

$ErrorActionPreference = "Stop"

function Test-Command {
    param([Parameter(Mandatory)][string]$Name)

    if (-not (Get-Command $Name -ErrorAction SilentlyContinue)) {
        throw "Required command '$Name' was not found."
    }
}

Write-Host "Checking Docker..." -ForegroundColor Cyan
Test-Command -Name "docker"

docker info | Out-Null
if ($LASTEXITCODE -ne 0) {
    throw "Docker Engine is not running. Start Docker Desktop."
}

$composeVersion = docker compose version
if ($LASTEXITCODE -ne 0) {
    throw "Docker Compose v2 is unavailable."
}
Write-Host $composeVersion -ForegroundColor Green

Write-Host "Creating Airflow project..." -ForegroundColor Cyan
New-Item -ItemType Directory -Force $ProjectPath | Out-Null
Set-Location $ProjectPath

"dags", "logs", "plugins", "config" |
    ForEach-Object {
        New-Item -ItemType Directory -Force $_ | Out-Null
    }

$composeUrl =
    "https://airflow.apache.org/docs/apache-airflow/" +
    "$AirflowVersion/docker-compose.yaml"

Write-Host "Downloading $composeUrl" -ForegroundColor Cyan
Invoke-WebRequest `
    -Uri $composeUrl `
    -OutFile "docker-compose.yaml"

'AIRFLOW_UID=50000' |
    Set-Content -Encoding ascii ".env"

Write-Host "Initializing Airflow..." -ForegroundColor Cyan
docker compose up airflow-init
if ($LASTEXITCODE -ne 0) {
    throw "Airflow initialization failed."
}

Write-Host "Starting Airflow..." -ForegroundColor Cyan
docker compose up -d
if ($LASTEXITCODE -ne 0) {
    throw "Airflow startup failed."
}

Write-Host "Container status:" -ForegroundColor Cyan
docker compose ps

Write-Host ""
Write-Host "Airflow URL: http://localhost:8080" -ForegroundColor Green
Write-Host "Username: airflow" -ForegroundColor Green
Write-Host "Password: airflow" -ForegroundColor Green

Start-Process "http://localhost:8080"

Run it

Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

26. Troubleshooting

Docker command is not recognized

Install Docker Desktop, close and reopen PowerShell, and confirm Docker Desktop is running. Check:

Get-Command docker
docker --version
Docker Desktop says WSL update is required
wsl --update
wsl --shutdown

Restart Docker Desktop after the commands complete.

Hardware-assisted virtualization is disabled

Enable Intel Virtualization Technology, VT-x, AMD-V, or SVM in BIOS/UEFI. The exact menu differs by manufacturer.

Airflow containers keep restarting or become unhealthy
  • Confirm sufficient memory is available.
  • Close memory-heavy applications.
  • Run docker compose ps.
  • Inspect API server, scheduler, PostgreSQL, and Redis logs.
  • Restart WSL and Docker Desktop.
wsl --shutdown
docker compose down
docker compose up -d
Port 8080 is already in use
Get-NetTCPConnection -LocalPort 8080 |
  Select-Object LocalAddress, LocalPort, State, OwningProcess

Get-Process -Id <OwningProcessId>

Stop the conflicting application or change the Airflow host port in docker-compose.yaml from 8080:8080 to another host port such as 8081:8080. Then open http://localhost:8081.

DAG does not appear
  1. Confirm the file is under C:\AirflowLab\dags.
  2. Confirm it ends with .py.
  3. Run the import-error command.
  4. Inspect DAG Processor logs.
  5. Confirm the DAG factory function is called.
docker compose run --rm airflow-worker `
  airflow dags list-import-errors

docker compose logs --tail 200 airflow-dag-processor
ModuleNotFoundError in a DAG

The module must exist inside the Airflow image, not only on Windows. Build a custom Airflow image with a pinned requirements.txt. Keep the Airflow package version equal to the base image version.

Task remains queued
  • Check worker and Redis health.
  • Check pool availability.
  • Check concurrency and parallelism.
  • Inspect worker logs.
Task cannot connect to a service on Windows localhost

Inside a container, localhost means the container itself. For a suitable service running on the Windows host, use host.docker.internal instead.

PowerShell blocks setup-airflow.ps1
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

This changes policy only for the current PowerShell process.

Clean reset after a broken learning environment
This deletes the Airflow learning database and all run history.
Set-Location C:\AirflowLab
docker compose down --volumes --remove-orphans
docker compose up airflow-init
docker compose up -d

30. Interview Questions and Answers

1. Can Apache Airflow run natively on Windows?

Airflow is designed for POSIX-compatible systems. On Windows, use WSL 2 or Linux containers. The Docker Desktop approach is recommended for this local learning lab.

2. Why is WSL 2 used with Docker Desktop?

WSL 2 provides a real Linux kernel environment that Docker Desktop uses to run Linux containers efficiently on Windows.

3. Why are Python and PostgreSQL not installed separately?

The official Compose stack provides Airflow, Python runtime, PostgreSQL, Redis, and Airflow services inside containers.

4. What is the purpose of docker-compose.yaml?

It declaratively defines the containers, networks, volumes, ports, environment variables, health checks, and dependencies required for the local Airflow stack.

5. What does airflow-init do?

It performs initialization, database migrations, and creation of the default learning account before the normal services start.

6. Why is PostgreSQL required?

It stores Airflow metadata such as DAG runs, task-instance states, configuration metadata, and operational history.

7. Why is Redis included?

The local Compose stack uses CeleryExecutor, and Redis acts as the message broker that carries queued task work to the worker.

8. What is the API server in Airflow 3?

It provides the web UI and REST API endpoint, exposed locally on port 8080 in this lab.

9. Scheduler versus worker?

The Scheduler decides which task instances are ready and queues them. The Worker executes the task code.

10. What is the DAG Processor?

It imports, parses, and serializes DAG definitions so Airflow knows their structure and configuration.

11. Grid View versus Graph View?

Grid View compares task states across runs. Graph View displays dependency structure and failure propagation within a selected run.

12. Where do you inspect task errors?

Open the task instance and read the Logs tab, beginning with the final exception and traceback.

13. What is Rendered Templates?

It shows templated operator fields after Airflow substitutes logical dates, parameters, macros, and runtime context.

14. What is XCom?

XCom is a mechanism for exchanging small metadata values between tasks. Large datasets should be stored externally.

15. What is a Pool?

A Pool limits the number of concurrent task slots assigned to a constrained resource such as a database or API.

16. Why does localhost fail from inside a container?

Inside a container, localhost identifies that container. Use the Compose service name for another container or host.docker.internal for an appropriate Windows-host service.

17. How do you diagnose a DAG that does not appear?

Check the mounted DAG folder, file extension, DAG factory invocation, DAG Processor logs, and airflow dags list-import-errors.

18. Why can a task remain queued?

The worker, executor, Redis, pool, queue, parallelism, or concurrency capacity may prevent execution.

19. What happens when you clear a task?

Its state is reset so Airflow can schedule it again. Depending on the selection, downstream or upstream instances may also be cleared.

20. Why should tasks be idempotent?

Retries and manual clears are normal. Re-execution must not duplicate data or corrupt output.

21. How do you stop Airflow without deleting history?

Use docker compose stop or docker compose down without deleting named volumes.

22. How do you completely reset the learning environment?

Use docker compose down --volumes --remove-orphans, then initialize and start the stack again. This deletes local run history.

23. Is this Compose environment suitable for production?

No. It is intended for learning and exploration and does not provide the security and high availability expected in production.

24. What is an Asset in Airflow?

An Asset is a logical data object that tasks can produce or consume, enabling lineage views and data-aware scheduling.

25. How do teams deploy DAGs in production?

DAGs are version-controlled, statically checked, import-tested, reviewed, and deployed through CI/CD into a secured managed or self-operated Airflow platform.
