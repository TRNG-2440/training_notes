2. What Is Streaming?

Streaming is the continuous movement and processing of data events as soon as, or shortly after, they are generated.

An event may be a food order, card payment, sensor reading, website click, GPS location, application log, or social-media message. Instead of waiting for an entire day’s data, a streaming system handles events continuously.

Simple idea: Batch processing is like collecting all exam papers and correcting them at night. Streaming is like checking every answer immediately as the student submits it.
LIVE
L — Listen to incoming events
I — Inspect and validate the data
V — Value is calculated through transformations
E — Emit the result to a dashboard, database, alert, or another application

Important Characteristics

Continuous

Events keep arriving without a fixed end.

Low Latency

Results are produced in seconds or milliseconds.

Event Driven

Each event can trigger processing or an action.

Scalable

The system must handle changing event volumes.

3. Batch Processing vs Streaming Processing

AreaBatch ProcessingStreaming Processing
Data arrivalCollected over a periodContinuously generated
Processing timeScheduled, such as hourly or dailyImmediately or near real time
Typical latencyMinutes to hoursMilliseconds to seconds
ExampleDaily sales reportLive fraud alert
Data sizeLarge bounded datasetUnbounded sequence of events
Main question“What happened yesterday?”“What is happening now?”
Streaming does not replace batch processing. Most real systems use both: streaming for immediate action and batch processing for historical reporting, reconciliation, and complex analytics.

Component Explanation

1. Producer

An application or device that creates events. Example: the customer mobile app creates an order event.

2. Broker

A durable event transport layer. It receives events, keeps them ordered within partitions, and allows consumers to read them.

3. Stream Processor

Reads events, validates them, transforms fields, performs aggregations, and detects patterns.

4. State Store

Stores intermediate information required for windows, joins, counts, and deduplication.

5. Sink

The destination for processed results, such as a database, Delta table, dashboard, or alerting system.

6. Consumer

The user or application that uses the result, such as a customer-tracking screen.

6. Core Streaming Concepts

6.1 Event

A small record that represents something that happened at a particular time.

6.2 Unbounded Data

A stream normally has no fixed end. More events may continue to arrive.

6.3 Event Time and Processing Time

Time TypeMeaningFood-Delivery Example
Event timeWhen the event actually occurredThe driver reached the restaurant at 10:15:05.
Processing timeWhen the streaming engine processed itThe server processed the update at 10:15:08.

6.4 Window

A window groups events from a time interval. For example, calculate the number of orders received during every five-minute period.

6.5 Watermark

A watermark tells the engine how long to wait for late events. It helps control the amount of state retained by the streaming query.

6.6 Checkpoint

A checkpoint stores progress and state so that a failed streaming job can restart without reprocessing everything from the beginning.

6.7 Delivery Guarantees

GuaranteeMeaning
At most onceAn event may be lost, but it is not processed more than once.
At least onceAn event is not lost, but duplicates are possible.
Exactly onceEach event affects the final result once, assuming the complete pipeline supports it.

8. PySpark Structured Streaming Demonstration

The following examples demonstrate the basic streaming workflow.

Example A: Socket Word Count

This example reads text continuously from a network socket and counts words.

1
Open a terminal and start a socket source 
ncat -lk 9999

On Linux or macOS, you may use: nc -lk 9999.

2
Create streaming_wordcount.py 
from pyspark.sql import SparkSession
from pyspark.sql.functions import explode, split

# Create the Spark session.
spark = (
    SparkSession.builder
    .appName("StreamingWordCount")
    .master("local[*]")
    .getOrCreate()
)

# Reduce unnecessary log output.
spark.sparkContext.setLogLevel("WARN")

# Read continuously arriving text from the socket.
lines_df = (
    spark.readStream
    .format("socket")
    .option("host", "localhost")
    .option("port", 9999)
    .load()
)

# Split every line into individual words.
words_df = lines_df.select(
    explode(split(lines_df["value"], " ")).alias("word")
)

# Maintain a running count for every word.
word_counts_df = words_df.groupBy("word").count()

# Write the continuously updated result to the console.
query = (
    word_counts_df.writeStream
    .outputMode("complete")
    .format("console")
    .option("truncate", "false")
    .start()
)

# Keep the application running until it is stopped.
query.awaitTermination()

Run the application

Example B: Food-Order File Streaming

Spark watches an input folder. Whenever a new JSON file is copied into the folder, Spark processes it as new streaming data. 

from pyspark.sql import SparkSession
from pyspark.sql.functions import col, count, sum as spark_sum
from pyspark.sql.types import (
    StructType, StructField, StringType,
    DoubleType, TimestampType
)

spark = (
    SparkSession.builder
    .appName("FoodOrderStreaming")
    .master("local[*]")
    .getOrCreate()
)

spark.sparkContext.setLogLevel("WARN")

# A streaming file source requires a predefined schema.
order_schema = StructType([
    StructField("event_id", StringType(), False),
    StructField("event_type", StringType(), False),
    StructField("order_id", StringType(), False),
    StructField("city", StringType(), True),
    StructField("order_amount", DoubleType(), True),
    StructField("event_time", TimestampType(), True)
])

# Read new JSON files arriving in the input directory.
orders_df = (
    spark.readStream
    .schema(order_schema)
    .json("data/incoming_orders")
)

# Retain only valid order-created events.
valid_orders_df = orders_df.filter(
    (col("event_type") == "ORDER_CREATED") &
    col("order_id").isNotNull() &
    (col("order_amount") > 0)
)

# Calculate live order count and sales amount by city.
city_summary_df = (
    valid_orders_df
    .groupBy("city")
    .agg(
        count("*").alias("order_count"),
        spark_sum("order_amount").alias("sales_amount")
    )
)

query = (
    city_summary_df.writeStream
    .outputMode("complete")
    .format("console")
    .option("truncate", "false")
    .option(
        "checkpointLocation",
        "checkpoints/food_order_summary"
    )
    .start()
)

query.awaitTermination()

Sample Input File: order_001.json

{"event_id":"EVT-001","event_type":"ORDER_CREATED","order_id":"ORD-1001","city":"Bengaluru","order_amount":18.50,"event_time":"2026-07-27T10:15:08Z"}
{"event_id":"EVT-002","event_type":"ORDER_CREATED","order_id":"ORD-1002","city":"Chennai","order_amount":23.75,"event_time":"2026-07-27T10:15:11Z"}
Copy new files into the input folder; do not repeatedly modify the same file. File-streaming sources are designed to discover newly arrived files.

10. Best Practices

Design Practices

  • Define a clear event schema and version it.
  • Include a unique event identifier.
  • Store event time, not only processing time.
  • Make sink operations idempotent where possible.
  • Use checkpoints for recoverable state.

Operational Practices

  • Monitor input rate, processing rate, and delay.
  • Handle malformed events separately.
  • Plan for duplicate and late events.
  • Use partitioning to distribute load.
  • Set retention policies to control storage cost.

Streaming Metrics to Monitor

MetricWhat It Indicates
Input rateHow many events arrive per second.
Processing rateHow many events the engine processes per second.
Consumer lagHow far the consumer is behind the latest available event.
End-to-end latencyTime between event generation and usable output.
Failed recordsEvents rejected because of schema or data-quality problems.

12. Interview Questions and Answers

1. What is stream processing?
Stream processing is the continuous processing of events as they arrive, usually with low latency.
2. How is streaming different from batch processing?
Batch processing works on bounded data collected over time, while streaming works on a continuously arriving, usually unbounded sequence of events.
3. What is an event producer?
A producer is an application, device, or service that creates and publishes events.
4. Why is a message broker used?
A broker buffers events, decouples producers from consumers, supports scalable consumption, and improves reliability.
5. What is event time?
Event time is the time at which the real-world event occurred.
6. What is a time window?
A time window groups events that belong to a defined interval, such as orders received during each five-minute period.
7. What is a watermark?
A watermark defines how late an event may arrive and still be included in event-time processing.
8. Why are checkpoints important?
Checkpoints save query progress and state, allowing recovery after a failure.
9. What is consumer lag?
Consumer lag is the difference between the latest available event and the latest event processed by a consumer.
10. What is an idempotent operation?
An idempotent operation can be repeated without changing the final result beyond the first successful application.
11. What is late-arriving data?
It is an event that reaches the processing system later than expected compared with its event time.
12. What is a streaming sink?
A sink is the destination to which processed streaming results are written.
13. Name common stream-processing technologies.
Examples include Apache Spark Structured Streaming, Apache Flink, Kafka Streams, Azure Stream Analytics, and Google Cloud Dataflow.
14. Why is schema management important?
It prevents incompatible changes, helps validate events, and allows producers and consumers to evolve safely.
15. Give one end-to-end streaming use case.
A food-delivery application publishes order and driver events, processes them through a streaming engine, updates a live dashboard, and generates delay alerts.
