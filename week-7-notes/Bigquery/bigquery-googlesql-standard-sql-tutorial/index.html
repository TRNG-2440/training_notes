1. What Is BigQuery Standard SQL?

BigQuery Standard SQL is the former name of GoogleSQL. Google renamed “Google Standard SQL” to “GoogleSQL.” It is the recommended SQL dialect for new BigQuery projects.

GoogleSQL is BigQuery's ANSI-compliant SQL dialect. It is used to create resources, query data, transform rows, manage access and run multi-statement analytical scripts.

Standard SQL / GoogleSQL

  • Recommended for all new work.
  • ANSI-style SQL.
  • Supports joins, CTEs, arrays, structs, window functions, DDL and DML.
  • Uses backticks for fully qualified table names.

Legacy SQL

  • Older BigQuery-specific dialect.
  • Retained mainly for compatibility.
  • Not recommended for new projects.
  • Has different syntax and restrictions.

Simple GoogleSQL example

SELECT
  product_category,
  SUM(sales_amount) AS total_sales
FROM `my-project.retail_demo.orders`
GROUP BY product_category
ORDER BY total_sales DESC;

2. Why Use GoogleSQL?

Familiar syntax

Developers and analysts who know standard SQL can learn it quickly.

Large-scale analytics

The same query style works across very large distributed tables.

Advanced data

It supports nested ARRAY and STRUCT data common in analytics.

Resource creation

DDL creates schemas, tables, views, functions and other resources.

Data changes

DML inserts, updates, deletes and merges data in billing-enabled projects.

Cost visibility

BigQuery estimates bytes processed before an on-demand query runs.

5. Setup from Scratch in BigQuery Studio

Option A — BigQuery Sandbox

  1. Open Google Cloud Console.
  2. Search for BigQuery.
  3. Open BigQuery Studio.
  4. Sign in and create or select a project.
  5. Use Sandbox when you do not want to attach a billing account.
Sandbox limitation: Sandbox supports learning and queries but does not support DML statements such as INSERT, UPDATE and DELETE. Tables, views and partitions expire automatically after 60 days.

Option B — Billing-enabled project

Use this when you need DML, streaming, transfer services or production features. For the lab below, the SQL is divided into Sandbox-safe and billing-enabled sections.

Create the dataset through Console

  1. In Explorer, locate your project.
  2. Click the three-dot View actions menu.
  3. Select Create dataset.
  4. Dataset ID: retail_standard_sql.
  5. Choose a location such as US. Keep all related resources in the same location.
  6. For training, set a default table expiration such as one day when the UI permits.
  7. Click Create dataset.

Create with GoogleSQL instead

CREATE SCHEMA IF NOT EXISTS `YOUR_PROJECT_ID.retail_standard_sql`
OPTIONS (
  location = 'US',
  description = 'Temporary GoogleSQL training dataset'
);

6. End-to-End Retail Demo

Replace every occurrence of YOUR_PROJECT_ID with your actual Google Cloud project ID.

Step 1 — Create a table with sample data

This uses DDL with CREATE TABLE AS SELECT, avoiding INSERT so the main demo is suitable for Sandbox.

CREATE OR REPLACE TABLE
  `YOUR_PROJECT_ID.retail_standard_sql.orders`
OPTIONS (
  description = 'Temporary retail orders training table',
  expiration_timestamp = TIMESTAMP_ADD(CURRENT_TIMESTAMP(), INTERVAL 1 DAY)
)
AS
SELECT * FROM UNNEST([
  STRUCT(1001 AS order_id, DATE '2026-07-01' AS order_date,
         'Bengaluru' AS city, 'Electronics' AS category,
         'Laptop' AS product, 1 AS quantity, 55000.00 AS unit_price,
         5.0 AS discount_pct, 'Delivered' AS status),
  STRUCT(1002, DATE '2026-07-01', 'Chennai', 'Grocery',
         'Rice Bag', 2, 1200.00, 0.0, 'Delivered'),
  STRUCT(1003, DATE '2026-07-02', 'Hyderabad', 'Electronics',
         'Headphones', 2, 3000.00, 10.0, 'Delivered'),
  STRUCT(1004, DATE '2026-07-02', 'Bengaluru', 'Furniture',
         'Office Chair', 1, 8500.00, 8.0, 'Shipped'),
  STRUCT(1005, DATE '2026-07-03', 'Pune', 'Clothing',
         'Formal Shirt', 3, 1800.00, 12.0, 'Delivered'),
  STRUCT(1006, DATE '2026-07-03', 'Chennai', 'Electronics',
         'Smartphone', 1, 32000.00, 6.0, 'Cancelled'),
  STRUCT(1007, DATE '2026-07-04', 'Mumbai', 'Grocery',
         'Cooking Oil', 4, 950.00, 3.0, 'Delivered'),
  STRUCT(1008, DATE '2026-07-04', 'Bengaluru', 'Electronics',
         'Monitor', 2, 14000.00, 7.0, 'Delivered'),
  STRUCT(1009, DATE '2026-07-05', 'Hyderabad', 'Furniture',
         'Study Table', 1, 12000.00, 5.0, 'Shipped'),
  STRUCT(1010, DATE '2026-07-05', 'Pune', 'Clothing',
         'Shoes', 2, 3500.00, 15.0, 'Delivered')
]);

Step 2 — Preview the rows

SELECT *
FROM `YOUR_PROJECT_ID.retail_standard_sql.orders`
ORDER BY order_id;

Step 3 — Build a calculated result

SELECT
  order_id,
  city,
  category,
  quantity,
  unit_price,
  discount_pct,
  ROUND(
    quantity * unit_price * (1 - discount_pct / 100),
    2
  ) AS net_amount
FROM `YOUR_PROJECT_ID.retail_standard_sql.orders`;

Step 4 — Aggregate sales

SELECT
  category,
  COUNT(*) AS order_lines,
  SUM(quantity) AS units,
  ROUND(SUM(quantity * unit_price *
      (1 - discount_pct / 100)), 2) AS net_sales
FROM `YOUR_PROJECT_ID.retail_standard_sql.orders`
WHERE status != 'Cancelled'
GROUP BY category
ORDER BY net_sales DESC;

Step 5 — Create a view

CREATE OR REPLACE VIEW
  `YOUR_PROJECT_ID.retail_standard_sql.delivered_orders_v`
AS
SELECT
  order_id,
  order_date,
  city,
  category,
  product,
  ROUND(quantity * unit_price *
    (1 - discount_pct / 100), 2) AS net_amount
FROM `YOUR_PROJECT_ID.retail_standard_sql.orders`
WHERE status = 'Delivered';

Step 6 — Query the view

SELECT city, ROUND(SUM(net_amount), 2) AS delivered_sales
FROM `YOUR_PROJECT_ID.retail_standard_sql.delivered_orders_v`
GROUP BY city
ORDER BY delivered_sales DESC;

7. Important GoogleSQL Query Examples

CTE

WITH sales AS (
  SELECT category,
         quantity * unit_price *
         (1 - discount_pct / 100) AS net_amount
  FROM `YOUR_PROJECT_ID.retail_standard_sql.orders`
  WHERE status != 'Cancelled'
)
SELECT category, ROUND(SUM(net_amount), 2) AS total_sales
FROM sales
GROUP BY category;

Window function

SELECT
  city,
  product,
  quantity * unit_price AS gross_amount,
  RANK() OVER (
    PARTITION BY city
    ORDER BY quantity * unit_price DESC
  ) AS city_rank
FROM `YOUR_PROJECT_ID.retail_standard_sql.orders`;

QUALIFY

SELECT
  city,
  product,
  quantity * unit_price AS gross_amount
FROM `YOUR_PROJECT_ID.retail_standard_sql.orders`
QUALIFY ROW_NUMBER() OVER (
  PARTITION BY city
  ORDER BY quantity * unit_price DESC
) = 1;

9. DML — Billing-Enabled Projects Only

Do not run this section in BigQuery Sandbox because Sandbox does not support DML.

Insert

INSERT INTO `YOUR_PROJECT_ID.retail_standard_sql.orders`
VALUES (1011, DATE '2026-07-06', 'Delhi', 'Electronics',
        'Keyboard', 2, 2200.00, 5.0, 'Delivered');

Update

UPDATE `YOUR_PROJECT_ID.retail_standard_sql.orders`
SET status = 'Delivered'
WHERE order_id = 1004;

Delete rows

DELETE FROM `YOUR_PROJECT_ID.retail_standard_sql.orders`
WHERE status = 'Cancelled';
Deleting rows is not the same as deleting the table. DELETE changes rows but keeps table storage and metadata. DROP TABLE removes the table resource.

11. Cost Reduction Before and During Queries

1. Check estimated processing

Before clicking Run, review the bytes BigQuery estimates the query will process.

2. Avoid SELECT *

Select only columns needed for the result. LIMIT does not necessarily reduce bytes scanned.

3. Partition large tables

Filter directly on the partition column so BigQuery can prune partitions.

4. Cluster suitable columns

Use frequently filtered or grouped columns to improve block pruning.

5. Set expiration

Use dataset defaults or table-level expiration for temporary training resources.

6. Use quotas

For on-demand billing, project-level or user-level custom query quotas can enforce hard limits.

Set an expiration on an existing table

ALTER TABLE `YOUR_PROJECT_ID.retail_standard_sql.orders`
SET OPTIONS (
  expiration_timestamp =
    TIMESTAMP_ADD(CURRENT_TIMESTAMP(), INTERVAL 1 DAY)
);
Current free usage: BigQuery's free tier includes the first 10 GiB of storage and first 1 TiB of query data processed per month, subject to Google's current pricing rules.

12. Complete Cleanup After the Lab

Recommended one-command cleanup

This removes the dataset and all tables and views inside it.

DROP SCHEMA IF EXISTS
  `YOUR_PROJECT_ID.retail_standard_sql`
CASCADE;
CASCADE is destructive. Confirm that the dataset contains only temporary lab resources before running it.

Granular cleanup

DROP VIEW IF EXISTS
  `YOUR_PROJECT_ID.retail_standard_sql.delivered_orders_v`;

DROP TABLE IF EXISTS
  `YOUR_PROJECT_ID.retail_standard_sql.orders`;

DROP SCHEMA IF EXISTS
  `YOUR_PROJECT_ID.retail_standard_sql`;

Console cleanup

  1. Open BigQuery Studio.
  2. In Explorer, expand the project.
  3. Open Datasets.
  4. Select retail_standard_sql.
  5. Click the three-dot View actions menu.
  6. Select Delete.
  7. Type delete in the confirmation dialog.
  8. Click Delete.

When to delete the entire project

When you created a separate project only for training, deleting the project is the most complete cleanup because it removes resources across BigQuery and other Google Cloud services. Check that the project contains no required resources first.

Post-cleanup checklist

  • Refresh Explorer and confirm the dataset is gone.
  • Check for scheduled queries, data transfers, connections and reservations created separately.
  • Check Cloud Storage buckets if files were uploaded there.
  • Check billing reports when billing was enabled.
  • Do not delete public datasets; they belong to Google and are only queried by your project.

17. Interview Questions and Answers

1. What is BigQuery Standard SQL?

It is the former name of GoogleSQL, BigQuery's recommended ANSI-compliant SQL dialect.

2. Why was it renamed?

Google Standard SQL is now branded GoogleSQL; the underlying BigQuery dialect remains the preferred modern syntax.

3. What is the difference between GoogleSQL and Legacy SQL?

GoogleSQL is the recommended ANSI-style dialect with modern features. Legacy SQL is the older compatibility dialect.

4. What are backticks used for?

They quote identifiers such as fully qualified table names: project.dataset.table.

5. What is a fully qualified table name?

A table reference containing project ID, dataset ID and table ID.

6. What is CTAS?

CREATE TABLE AS SELECT creates a table using the result of a query.

7. What is the difference between DELETE and DROP TABLE?

DELETE removes matching rows. DROP TABLE removes the whole table resource.

8. What is DROP SCHEMA CASCADE?

It deletes a dataset and the objects contained in it. It must be used carefully.

9. How can training resources be removed automatically?

Set default dataset expiration or table-level expiration timestamps.

10. What are the main BigQuery costs?

Compute for query processing and storage for data kept in BigQuery.

11. How do you reduce query cost?

Select required columns, filter partitions, use clustering, inspect bytes estimates and enforce quotas.

12. Is BigQuery Sandbox free?

It provides limited BigQuery capabilities without a billing account, subject to sandbox and free-tier limits.

13. Why might INSERT fail in Sandbox?

Sandbox does not support DML statements.

14. What are ARRAY and STRUCT?

They are GoogleSQL data types used for repeated and nested data.

15. What is QUALIFY?

It filters rows after window functions are evaluated.
