Section 2

Traditional approach and drawbacks

Traditional approach

  • Relational databases processed structured data on one server or an expensive scale-up appliance.
  • Hadoop MapReduce programs handled very large files through multiple map, shuffle and reduce stages.
  • Each stage frequently wrote intermediate output to disk.
  • SQL, ETL code, machine learning and streaming often used different tools.

Drawbacks

ProblemEffect
Repeated disk I/OLonger iterative processing.
Manual low-level codeMore development and maintenance effort.
Separate technologiesMore integration and operational complexity.
Limited query-plan visibilityThe system cannot optimize arbitrary procedural code as effectively as structured expressions.
Scale-up dependenceLarge servers become expensive and eventually reach limits.
Section 3

What is Spark SQL and why use it?

Definition: Spark SQL is the Spark module for structured and semi-structured data processing using SQL, DataFrames and Datasets.

Why use it?

  • Query CSV, JSON, Parquet, ORC, Hive tables and JDBC sources.
  • Use familiar SQL and programmatic DataFrame expressions in one engine.
  • Let Spark analyze and optimize the logical query plan.
  • Run the same logic locally or on a distributed cluster.
  • Write results to analytical formats and managed tables.

Who uses it?

RoleTypical work
Data engineerETL, validation, enrichment, joins and aggregation.
Analytics engineerBusiness transformations and reusable SQL models.
Data analystLarge SQL queries and report datasets.
Data scientistFeature preparation before modeling.
Platform engineerCompute, catalogs, security and job operations.
Section 4

What is SparkSession?

Definition: SparkSession is the modern entry point for DataFrame, Dataset, SQL, catalog and data-source functionality.

from pyspark.sql import SparkSession

spark = (
    SparkSession.builder
    .appName("Retail Spark SQL Demo")
    .master("local[*]")
    .getOrCreate()
)
Method or propertyPurpose
spark.readLoad files, tables and JDBC data.
spark.createDataFrame()Create a DataFrame from local data or an RDD.
spark.sql()Execute SQL and return a DataFrame.
spark.catalogWork with tables, databases and views.
spark.sparkContextAccess low-level classic Spark/RDD functionality when supported.
Section 5

Why is SparkSession called the entry point?

An entry point is the first object an application uses to access a framework. SparkSession gives one object named spark for reading data, creating DataFrames, executing SQL and using the catalog.

Local Python file

You create spark with SparkSession.builder.

PySpark shell

The shell normally creates spark automatically.

Databricks notebook

The notebook runtime provides spark automatically.

Trainer rule: all new Spark SQL and DataFrame applications should begin from SparkSession.

from common import create_local_spark
def main():
    spark=create_local_spark('02-Session-Vs-Context'); sc=spark.sparkContext

        print('SparkSession object:',spark); print('SparkContext object:',sc)

SQLContextDataFrame and SQL functionality before Spark 2.0.SparkSession

"""Historical SQLContext and HiveContext compatibility demo."""
from pyspark.sql import SQLContext,HiveContext
from common import create_local_spark
def main():
    spark=create_local_spark('03-Legacy-Contexts'); sc=spark.sparkContext
    try:
        sql_context=SQLContext.getOrCreate(sc); hive_context=HiveContext(sc)
        print('SparkSession:',type(spark).__name__);print('SQLContext:',type(sql_context).__name__);print('HiveContext:',type(hive_context).__name__)
        df=sql_context.createDataFrame([('Electronics',131540.0),('Fashion',19340.0),('Grocery',5744.0)],['category','revenue'])
        df.createOrReplaceTempView('legacy_sales')
        hive_context.sql('SELECT category,revenue FROM legacy_sales ORDER BY revenue DESC').show()
        print('Use SparkSession for all new applications.')
    finally: spark.stop()
if __name__=='__main__': main()
Do not use SQLContext or HiveContext in new projects. They remain mainly for backward compatibility and migration.
Section 8

Introduction to DataFrames

Definition: A DataFrame is a distributed collection of rows organized into named columns. It is similar to a relational table but processed across Spark partitions.

FeatureMeaning
SchemaColumn names and data types.
DistributedRows are divided into partitions.
ImmutableEach transformation creates a new logical DataFrame.
LazyTransformations build a plan; actions trigger execution.
OptimizedSpark SQL can analyze expressions and optimize plans.
orders_df = (
    spark.read
    .option("header", True)
    .option("inferSchema", True)
    .csv("data/retail_orders.csv")
)

orders_df.printSchema()
orders_df.show()
No StructType required for this demo. Spark infers the schema from the training CSV. Production pipelines should control schema explicitly when reliability and schema evolution matter.
Section 9

How DataFrame and Spark SQL execution works

  1. Source data becomes a DataFrame.
  2. DataFrame operations or SQL create a logical plan.
  3. Spark analyzes column and table references.
  4. The optimizer simplifies and improves the plan.
  5. A physical plan selects joins, exchanges and operators.
  6. Executors process partitions and produce output.

Section 11

Complete local practical demo

Business requirement

Read retail orders, calculate gross and net amount, keep completed transactions, aggregate category revenue and save a report in Parquet.

Data flow

CSV → DataFrame → calculated columns → temporary view → Spark SQL → Parquet → reload and verify
Complete executable code
"""End-to-end Spark SQL retail report."""
import shutil
from pyspark.sql import functions as F
from common import DATA_DIR,OUTPUT_DIR,create_local_spark
def main():
    spark=create_local_spark('05-End-to-End-Spark-SQL')
    try:
        df=(spark.read.option('header',True).option('inferSchema',True).csv(str(DATA_DIR/'retail_orders.csv')))
        prepared=(df.withColumn('gross_amount',F.col('quantity')*F.col('unit_price')).withColumn('net_amount',F.round(F.col('gross_amount')*(1-F.col('discount_pct')/100),2)))
        prepared.createOrReplaceTempView('retail_orders')
        report=spark.sql("""SELECT category,COUNT(*) completed_orders,SUM(quantity) units_sold,ROUND(SUM(net_amount),2) total_net_revenue,ROUND(AVG(net_amount),2) average_order_value FROM retail_orders WHERE status='COMPLETED' GROUP BY category ORDER BY total_net_revenue DESC""")
        report.show(truncate=False);report.explain(mode='formatted')
        out=OUTPUT_DIR/'category_sales_report_parquet'
        if out.exists(): shutil.rmtree(out)
        report.write.mode('overwrite').parquet(str(out))
        print('Saved Parquet:',out);spark.read.parquet(str(out)).show(truncate=False)
    finally: spark.stop()
if __name__=='__main__': main()

Apache Spark Web UI

Every active classic SparkContext starts an application Web UI. The default local address is:

http://localhost:4040
TabWhat it shows
JobsActions and job status.
StagesTasks, shuffle, input and output metrics.
StorageCached DataFrames and RDDs.
EnvironmentSpark properties and classpath.
ExecutorsMemory, cores, tasks and errors.
SQL/DataFrameQuery plans and SQL execution details.
The local UI exists only while the Spark application is running. The first demo pauses before stopping so you can inspect it.
"""Create and inspect SparkSession."""
from common import create_local_spark
def main():
    spark=create_local_spark('01-SparkSession-EntryPoint')
    try:
        print('Spark version:',spark.version)
        print('Application name:',spark.sparkContext.appName)
        print('Master:',spark.sparkContext.master)
        print('Spark UI:',spark.sparkContext.uiWebUrl)
        print('Catalog implementation:',spark.conf.get('spark.sql.catalogImplementation'))

    finally: spark.stop()

Section 16

Best practices and version guidance

  • Use SparkSession for new code.
  • Prefer DataFrame and Spark SQL APIs for structured workloads.
  • Define schemas explicitly in production when source quality matters.
  • Select only required columns before joins and aggregation.
  • Use Parquet or Delta for analytical persistence.
  • Avoid driver-side collect() for large results.
  • Inspect explain() and Spark UI before changing memory settings.
  • Do not force .master('local[*]') in Databricks or cluster-submitted applications.
  • Treat SQLContext and HiveContext as migration knowledge.

Spark 4.xSparkSession, DataFrame/SQL and Spark Connect where applicable
