GCP Dataproc + GCS + PySpark

A simple end-to-end retail sales demo for someone new to Google Cloud Console: architecture, Console and CLI, Cloud Storage as the durable HDFS replacement, IAM, job submission, verification, troubleshooting and cleanup.

1. Learning outcome and demo story

Scenario: A retail company receives a CSV of store sales. You will keep the input and PySpark program in a Cloud Storage bucket, run the program on a Dataproc Spark cluster, and write a city/category summary back to the bucket as Parquet.

sales.csvRaw retail records
GCS input/Durable object storage
DataprocManaged Spark cluster
PySparkClean + aggregate
GCS output/Parquet report

What you will prove

Cost rule: A running Dataproc cluster uses Compute Engine VMs and incurs charges even while idle. Delete it immediately after the lab. Charges and quotas vary by region and account; check the Pricing Calculator before classroom use.

2. Key concepts in plain language

Google Cloud Console

Browser-based interface to create and inspect projects, buckets, clusters, jobs, IAM and logs.

Google Cloud CLI

gcloud commands for repeatable administration. Cloud Shell already includes the CLI and signs in with your Google identity.

Dataproc

Google Cloud’s managed service for Apache Spark and Hadoop. It creates the required VMs, installs software and manages job submission.

Cloud Storage (GCS)

Durable object storage. A bucket is a global-name container; files stored inside it are objects addressed with gs://bucket/path.

PySpark

Python API for Apache Spark. The driver plans work and executors process distributed partitions.

IAM

Identity and Access Management controls who can perform which actions on which resources.

3. Dataproc cluster architecture

Google-managed control plane

Dataproc API receives create/delete/job requests, provisions resources, reports status and integrates with IAM, logging and monitoring.

You interact through: Console, gcloud, REST APIs or client libraries.

Your project’s data plane

Primary
Spark driver, YARN ResourceManager, HDFS NameNode
Worker 1
Executors, NodeManager, DataNode
Worker 2
Executors, NodeManager, DataNode

Compute Engine VMs execute the job. This tutorial uses a single-node training cluster, so primary and worker functions share one VM.

Conceptual view. Exact installed components depend on the Dataproc image and cluster configuration.

Spark execution inside the cluster

ComponentResponsibilityRetail example
DriverCreates SparkSession, builds the execution plan and coordinates stages.Plans read → clean → groupBy → write.
YARN ResourceManagerAllocates cluster resources to applications.Grants CPU/memory containers to the Spark job.
ExecutorsRun tasks over data partitions and return results/metrics.Aggregate sales records by city and category.
GCS ConnectorLets Hadoop/Spark APIs access gs:// objects.Reads CSV and writes Parquet without copying data into HDFS.

GCS as the HDFS replacement

AreaHDFSCloud Storage
Addresshdfs:///data/sales.csvgs://my-bucket/input/sales.csv
LocationCluster disksIndependent managed object storage
After cluster deletionData is normally lost with cluster disksObjects remain until separately deleted
ScalingStorage and compute are coupledStorage and compute scale independently
SemanticsTrue distributed filesystemObject store exposed through a connector; not identical to POSIX/HDFS
Memory aid: HDFS is the cluster’s cupboard. GCS is the warehouse outside the cluster. You can replace the workers without throwing away the warehouse.

4. IAM roles for data workloads

Two identities matter. Do not mix them:

1. Your user identity

Creates buckets/clusters and submits jobs through Console or Cloud Shell.

2. Cluster VM service account

Used by Dataproc VMs at runtime to read input, write output and publish logs.

Practical least-privilege role guide

IdentityTypical roleWhy
Lab userDataproc Editor (roles/dataproc.editor)Create/delete clusters and submit/manage jobs. Exact tasks may need extra permissions.
Lab userService Account User (roles/iam.serviceAccountUser) on the selected VM service accountAllows attaching/acting as that service account when creating the cluster.
Lab userStorage Admin (roles/storage.admin) for a self-contained labCreate/delete bucket and manage objects. Narrow this in production.
Cluster VM service accountDataproc Worker (roles/dataproc.worker)Required worker-node operations.
Cluster VM service accountStorage Object Viewer on input + Storage Object Creator/Admin on outputRead the CSV/script and write results. Object Admin is simpler for a disposable lab.
Never download a service-account JSON key for this lab. Use the service account attached to the Dataproc VM. Long-lived keys are unnecessary and risky.

Where to view roles in Console

  1. Open Navigation menu ☰ → IAM & Admin → IAM.
  2. Use View by principals to find your user or service account.
  3. For bucket-only access: Cloud Storage → Buckets → bucket name → Permissions.
  4. If your organization manages permissions, ask the administrator; do not grant broad Owner/Editor merely to bypass errors.

6. Console practical — bucket, files, cluster and job

A. Create the Cloud Storage bucket

Navigation menu ☰ → Cloud Storage → Buckets → Create.

Name: use the value shown by echo "$DP_BUCKET". It must be globally unique.

Location type: Region; Location: asia-south1 (Mumbai), matching the cluster. Default storage class: Standard.

Access control: Uniform. Keep public access prevention enabled. Keep other defaults and click Create.

B. Create the two local lab files in Cloud Shell

Use the following commands. They create a 12-row CSV and a PySpark application in your Cloud Shell home directory.

mkdir -p ~/dataproc-retail-demo
cd ~/dataproc-retail-demo

cat > sales.csv <<'CSV'
sale_id,sale_date,city,category,quantity,unit_price
S001,2026-07-01,Bengaluru,Electronics,1,55000
S002,2026-07-01,Chennai,Grocery,5,120
S003,2026-07-02,Bengaluru,Grocery,3,250
S004,2026-07-02,Mumbai,Clothing,2,1500
S005,2026-07-03,Chennai,Electronics,1,32000
S006,2026-07-03,Mumbai,Grocery,10,80
S007,2026-07-04,Bengaluru,Clothing,2,2200
S008,2026-07-04,Chennai,Clothing,1,1800
S009,2026-07-05,Mumbai,Electronics,2,28000
S010,2026-07-05,Bengaluru,Grocery,4,150
S011,2026-07-06,Chennai,Grocery,6,100
S012,2026-07-06,Mumbai,Clothing,3,1200
CSV
cat > retail_sales_job.py <<'PY'
import sys
from pyspark.sql import SparkSession
from pyspark.sql import functions as F
from pyspark.sql.types import (
    StructType, StructField, StringType,
    IntegerType, DoubleType
)

if len(sys.argv) != 3:
    raise ValueError(
        "Usage: retail_sales_job.py <input_gcs_path> <output_gcs_path>"
    )

input_path = sys.argv[1]
output_path = sys.argv[2]

spark = SparkSession.builder.appName("RetailSalesSummary").getOrCreate()

schema = StructType([
    StructField("sale_id", StringType(), False),
    StructField("sale_date", StringType(), True),
    StructField("city", StringType(), True),
    StructField("category", StringType(), True),
    StructField("quantity", IntegerType(), True),
    StructField("unit_price", DoubleType(), True)
])

sales_df = (
    spark.read
         .option("header", "true")
         .schema(schema)
         .csv(input_path)
)

clean_df = (
    sales_df
    .filter(F.col("quantity") > 0)
    .filter(F.col("unit_price") >= 0)
    .withColumn("sale_date", F.to_date("sale_date", "yyyy-MM-dd"))
    .withColumn("city", F.initcap(F.trim("city")))
    .withColumn("category", F.initcap(F.trim("category")))
    .withColumn("revenue", F.col("quantity") * F.col("unit_price"))
)

report_df = (
    clean_df
    .groupBy("city", "category")
    .agg(
        F.countDistinct("sale_id").alias("total_sales"),
        F.sum("quantity").alias("units_sold"),
        F.round(F.sum("revenue"), 2).alias("total_revenue")
    )
    .orderBy("city", F.desc("total_revenue"))
)

print("=== RETAIL SALES REPORT ===")
report_df.show(50, truncate=False)

(
    report_df.coalesce(1)
             .write
             .mode("overwrite")
             .parquet(output_path)
)

spark.stop()
PY

python3 -m py_compile retail_sales_job.py
echo "Files created and Python syntax validated."
Why explicit schema? It prevents Spark from scanning the file to guess types and makes expected column types clear. coalesce(1) is only for this tiny classroom report; avoid forcing one partition for large production data.

C. Upload through Console

  1. Cloud Storage → Buckets → your bucket.
  2. Click Create folder, enter input; open it and click Upload files → choose sales.csv.
  3. Return to bucket root, create folder code; upload retail_sales_job.py.
  4. The expected object paths are gs://BUCKET/input/sales.csv and gs://BUCKET/code/retail_sales_job.py.

Cloud Shell file download: click ⋮ in Cloud Shell → Download is for downloading to your computer. To upload directly from Cloud Shell, the CLI method below is simpler.

D. Create a low-cost training cluster in Console

Navigation menu ☰ → Dataproc → Clusters → Create cluster → Cluster on Compute Engine.

Name: retail-dp-cluster. Region: asia-south1. Keep a zone selection within that region.

Under cluster type/configuration, select Single node for this learning demo. This is not for production high availability.

Machine type: choose a small available general-purpose type with at least 2 vCPUs, such as e2-standard-2. Set primary boot disk to around 50 GB if the UI permits.

Choose the intended VM service account. Ensure it has Dataproc Worker and required bucket object permissions. Keep the current recommended Dataproc image/default unless your course mandates a version.

Click Create. Wait until status becomes Running. Provisioning can take several minutes.

E. Submit the PySpark job in Console

  1. Dataproc → Jobs → Submit job.
  2. Region: asia-south1; Cluster: retail-dp-cluster; Job type: PySpark.
  3. Main Python file: gs://YOUR_BUCKET/code/retail_sales_job.py.
  4. Arguments, in this order:
    • gs://YOUR_BUCKET/input/sales.csv
    • gs://YOUR_BUCKET/output/sales_summary
  5. Click Submit. Open the job and watch status/logs until it is Succeeded.

7. CLI practical — repeat the same workflow

The CLI is the most reliable way to repeat the lab. Run these in Cloud Shell after the variables in Section 5 are set.

A. Create bucket and upload files

gcloud storage buckets create "gs://${DP_BUCKET}" \
  --project="$DP_PROJECT" \
  --location="$DP_REGION" \
  --default-storage-class=STANDARD \
  --uniform-bucket-level-access

gcloud storage cp ~/dataproc-retail-demo/sales.csv \
  "gs://${DP_BUCKET}/input/sales.csv"

gcloud storage cp ~/dataproc-retail-demo/retail_sales_job.py \
  "gs://${DP_BUCKET}/code/retail_sales_job.py"

gcloud storage ls --recursive "gs://${DP_BUCKET}"

If you already created the bucket/files in Console, skip the create command; rerunning upload commands safely replaces those two objects.

B. Create a single-node cluster

gcloud dataproc clusters create "$DP_CLUSTER" \
  --project="$DP_PROJECT" \
  --region="$DP_REGION" \
  --single-node \
  --master-machine-type=e2-standard-2 \
  --master-boot-disk-size=50GB \
  --labels=purpose=training,owner=trainer

Inspect it:

gcloud dataproc clusters describe "$DP_CLUSTER" \
  --project="$DP_PROJECT" \
  --region="$DP_REGION" \
  --format="table(clusterName,status.state,config.masterConfig.machineTypeUri)"

C. Submit the job — important command syntax

gcloud dataproc jobs submit pyspark \
  "gs://${DP_BUCKET}/code/retail_sales_job.py" \
  --project="$DP_PROJECT" \
  --cluster="$DP_CLUSTER" \
  --region="$DP_REGION" \
  -- \
  "gs://${DP_BUCKET}/input/sales.csv" \
  "gs://${DP_BUCKET}/output/sales_summary"
What does -- mean? Flags before it belong to gcloud. Values after it are passed to your Python program as sys.argv[1] and sys.argv[2].

D. Useful CLI status commands

# List recent jobs
gcloud dataproc jobs list \

# Describe one job after replacing JOB_ID

End-to-end execution sequence

  1. The Dataproc service receives the job request.
  2. The Spark driver starts on the cluster and receives the two GCS paths.
  3. The GCS connector streams CSV objects to Spark using the cluster service account.
  4. Spark validates types, cleans records, creates revenue, shuffles by city/category and aggregates.
  5. The connector writes Parquet objects back to GCS.
  6. Because output is in GCS, it remains available after cluster deletion.

9. Cost-control cleanup

Do this before leaving the lab. Delete the Dataproc cluster first. Deleting a job record does not stop or delete the cluster.

Console cleanup

  1. Dataproc → Clusters → select retail-dp-cluster → Delete → confirm.
  2. Wait until the cluster disappears or reports deleted.
  3. If you no longer need the data: Cloud Storage → Buckets → select the lab bucket → Delete.

CLI cleanup

# 1. Delete compute first
gcloud dataproc clusters delete "$DP_CLUSTER" \
  --project="$DP_PROJECT" \
  --region="$DP_REGION" \
  --quiet

# 2. Confirm no lab cluster remains
gcloud dataproc clusters list \
  --project="$DP_PROJECT" \
  --region="$DP_REGION"

# 3. Delete the disposable bucket and all its objects
gcloud storage rm --recursive "gs://${DP_BUCKET}"

# 4. Confirm bucket removal
gcloud storage buckets list --project="$DP_PROJECT"
The recursive bucket deletion is destructive. Run it only after confirming echo "$DP_BUCKET" identifies the disposable lab bucket—not a shared or production bucket.

10. Common errors and fixes

PERMISSION_DENIED when creating the cluster

Check that your user can create Dataproc clusters and act as the selected VM service account. Typical missing access is Dataproc Editor or Service Account User. Your administrator may use a custom role instead.

403 while reading or writing gs://

The cluster VM service account, not only your user, needs object permissions on the bucket. Grant Viewer for input and Creator/Admin for output at the bucket level.

Bucket name already exists

Bucket names are global. Change DP_BUCKET, for example by appending a short unique suffix, then create again.

Region mismatch / cluster not found

The job’s --region must match the cluster region. Run gcloud dataproc clusters list --regions=all or check Dataproc → Clusters in Console.

PySpark job says input path does not exist

Run gcloud storage ls gs://BUCKET/input/. Check spelling, case and whether the bucket variable was expanded. GCS object names are case-sensitive.

Output path already exists

This script uses mode("overwrite"), so it should replace the old path. If an IAM rule blocks deletion of prior objects, use a new output folder or grant the precise delete permission required.

Quota or stockout error for the machine type

Choose another available zone/machine type in the same region, or request quota. Do not silently switch regions if the bucket’s regional placement is an important course requirement.

Command not found: gcloud

Use Google Cloud Shell, which already includes the CLI, or install and initialize the Google Cloud CLI locally with gcloud init.

11. Production improvements and edge cases

Training choiceProduction improvement
Single-node clusterUse multi-node or autoscaling clusters, or consider Dataproc Serverless for suitable batch workloads.
Object Admin for one bucketSeparate input/output buckets or prefixes and apply Viewer/Creator permissions narrowly.
inferSchema avoided; static schema usedStore versioned schemas and validate malformed records/quarantine paths.
coalesce(1)Retain parallel output files and manage file sizes through partitioning/compaction.
Overwrite outputUse partitioned, idempotent writes and atomic publication strategies.
Long-lived interactive clusterUse ephemeral job clusters/workflows, scheduled deletion and labels for cost attribution.

When HDFS may still appear

Dataproc clusters include HDFS for temporary/shuffle-adjacent or legacy use cases, but durable business data should normally live outside ephemeral cluster disks. GCS is not a perfect drop-in for every HDFS/POSIX behavior: rename-heavy algorithms, very small objects and assumptions about append semantics need review.

12. Interview questions with answers

1. What is Dataproc?
A managed Google Cloud service for running Apache Spark, Hadoop and related open-source data workloads on managed infrastructure.
2. What is the difference between Dataproc and Spark?
Spark is the processing engine. Dataproc is the cloud service that provisions, configures and manages environments where Spark jobs run.
3. Why use GCS instead of HDFS for durable data?
It decouples storage from compute, remains after cluster deletion, scales independently and can be accessed by multiple Google Cloud services.
4. What does the GCS connector do?
It allows Hadoop-compatible APIs and Spark to read and write Cloud Storage using gs:// paths.
5. What is the primary node?
It hosts coordination services such as the Spark driver for submitted jobs, YARN ResourceManager and HDFS NameNode, depending on configuration.
6. What do worker nodes do?
They provide CPU and memory for executors/tasks and may run YARN NodeManager and HDFS DataNode services.
7. Why must the cluster service account have GCS permissions?
The code runs using the VM runtime identity. Your personal ability to view a bucket does not automatically give the cluster access.
8. What does the double dash in the submit command mean?
It separates gcloud flags from arguments passed to the PySpark application.
9. Does deleting the Dataproc job delete the cluster?
No. Job records and cluster compute are separate resources. Delete the cluster explicitly to stop VM charges.
10. Why match the GCS and Dataproc region?
It generally reduces latency and avoids unnecessary inter-region data transfer considerations; exact costs depend on the service/location design.
11. Why is Parquet preferred over CSV for analytics?
Parquet is columnar, typed and compressed, allowing Spark to read only relevant columns and often reduce I/O.
12. What is a single-node cluster?
A non-HA cluster where primary and worker roles share one VM. It is useful for small experiments, not resilient production workloads.
13. Console or CLI—which is better?
Console is easier for exploration; CLI is more repeatable and automatable. Strong teams understand both.
14. How do you reduce Dataproc cost?
Use right-sized or autoscaling/ephemeral compute, delete idle clusters, use appropriate secondary workers where suitable, label resources and keep durable data in GCS.
15. What is the Spark driver versus executor?
The driver plans and coordinates the application. Executors run distributed tasks and store intermediate data on worker resources.
