PySpark Assignment: Smart Energy Utility Analytics

Scenario-based cohort exercise covering SparkSession, RDD transformations/actions, DataFrames, aggregation, ordering, execution plans and CSV processing.

Business Scenario

GridPulse Energy supplies electricity to residential, commercial and industrial customers across five operational zones. The operations team needs a PySpark solution to analyse meter consumption, billing, outages and payment status.

The assignment follows the same learning progression as the reference demos but uses a completely different industry scenario.

Provided Files

File Description Main columns
customers.csv Customer and tariff master customer_id, zone, connection_type, tariff_per_kwh
meter_readings.csv Daily meter consumption records reading_id, reading_date, customer_id, units_consumed, payment_status
outages.csv Electricity outage events outage_id, zone, duration_minutes, affected_customers, status
Important: The data deliberately contains duplicates, missing values, invalid dates, non-positive consumption/duration and inconsistent casing. Do not manually modify the CSV files.

Part A — SparkSession Runtime Inspection

  1. Create a SparkSession named EnergyUtilityAssignment using local[*]. (3)
  2. Set the Spark log level to ERROR. (1)
  3. Print Spark version, application name, master, default parallelism and CPU count. (4)
  4. Stop the SparkSession correctly. (2)

Part B — RDD Peak Consumption Analysis

Create an RDD from this list using two partitions:

[95, 240, 180, 410, 525, 160, 305, 275, 80, 620, 390, 145]
  1. Print the number of partitions. (3)
  2. Use filter() to keep readings greater than or equal to 300 units. (5)
  3. Use map() to convert each retained reading into (reading, "PEAK"). (4)
  4. Display peak-reading count using count(). (3)
  5. Display the first three peak readings using take(3). (3)
  6. Explain which operations are transformations and which are actions. (2)

Part C — RDD Outage Count by Zone

  1. Read outages.csv using spark.sparkContext.textFile(). Remove the header dynamically. (4)
  2. Parse each row and extract zone and status. Trim spaces and convert the status to uppercase. (4)
  3. Remove blank zones and retain only RESOLVED outages. (3)
  4. Use map() and reduceByKey() to calculate resolved-outage counts by zone. (5)
  5. Sort the output alphabetically using sortByKey() and print the results using collect(). (4)

Part D — In-Memory DataFrame Billing Summary

Create a DataFrame from the following data:

(201, "North", 1480.00)
(202, "South", 925.50)
(203, "North", 1710.25)
(204, "East", 2480.00)
(205, "South", 1195.75)
(206, "Central", 3450.50)
(207, "East", 1890.00)
(208, "West", 1325.25)

Use columns bill_id, zone and bill_amount.

  1. Create the DataFrame and display the original records. (4)
  2. Print the schema. (2)
  3. Group by zone and calculate bill count, total revenue and average bill. (8)
  4. Round monetary values to two decimal places. (3)
  5. Order the report by total revenue descending. (3)
  6. Display the report and call explain(). Identify two plan operators. (5)
