2. First Correct the Question

Hadoop vs Spark is not completely apples-to-apples. Hadoop often means HDFS + YARN + MapReduce. Spark is primarily a processing engine and does not replace HDFS storage.
LayerHadoopSpark
StorageHDFS stores replicated file blocks.Reads/writes HDFS, object stores, databases and tables; not a file system.
Resource managementYARN allocates cluster resources.Can run on YARN, Kubernetes or Spark Standalone.
ProcessingMapReduce mapper/shuffle/reducer batch model.RDD, DataFrame, SQL and structured-streaming execution.
Fair processing comparison: Hadoop MapReduce versus Spark.
Common combined solution: HDFS + YARN + Spark.

3. Hadoop Explained

HDFS

Files are divided into blocks stored on DataNodes. The NameNode manages namespace and block metadata.

YARN

The ResourceManager and application-specific ApplicationMaster coordinate resources and job execution.

MapReduce

Mappers emit key-value pairs; shuffle/sort groups keys; reducers aggregate and write output.

MAP: convert records into intermediate key-value pairs.
SHUFFLE: bring equal keys together.
REDUCE: combine values and write results.

MapReduce is a strong fit for durable, high-throughput batch jobs where longer latency and intermediate storage are acceptable.

4. Spark Explained

Spark DataFrame code describes a logical plan. An action triggers optimization, stage creation and tasks over partitions.

Driver

Runs the main application, builds plans and coordinates executors.

Executors

Worker processes that execute tasks and manage cached or shuffle data.

DAG / Stages

Transformations create dependencies; shuffle boundaries commonly separate stages.

Transformation: defines work such as filter.
Action: triggers work such as count, show or write.

Spark suits multi-stage ETL, interactive SQL, iterative processing and structured streaming. It can still spill to disk and perform expensive network shuffles.

6. Same Real-World Example — Retail Revenue

A retailer wants completed-order revenue grouped by city and category.

  1. Keep only COMPLETED.
  2. Reject invalid quantity, price or discount.
  3. Calculate quantity × unit price × (1 − discount/100).
  4. Group by city/category and sum revenue.
order_id,order_date,city,category,quantity,unit_price,discount_pct,status
1001,2026-07-01,Coimbatore,Electronics,2,25000,5,COMPLETED
1002,2026-07-01,Chennai,Grocery,10,120,0,COMPLETED
1004,2026-07-01,Coimbatore,Grocery,5,250,0,CANCELLED
Order 1001 contributes ₹47,500. Order 1002 contributes ₹1,200. The cancelled order contributes nothing.

7. Hadoop MapReduce Solution

Mapper

String[] f = line.split(",", -1);
String city = f[2].trim();
String category = f[3].trim();
int quantity = Integer.parseInt(f[4].trim());
long unitPrice = Long.parseLong(f[5].trim());
int discount = Integer.parseInt(f[6].trim());
String status = f[7].trim();

if (!"COMPLETED".equalsIgnoreCase(status)) return;

long netRevenuePaise =
    quantity * unitPrice * (100L - discount);

context.write(
    new Text(city + "|" + category),
    new LongWritable(netRevenuePaise)
);

The mapper performs record-level validation, creates the composite grouping key and emits revenue in paise.

Reducer

long totalPaise = 0L;
for (LongWritable value : values) {
    totalPaise += value.get();
}
context.write(key, new Text(
    BigDecimal.valueOf(totalPaise)
      .divide(BigDecimal.valueOf(100), 2, RoundingMode.HALF_UP)
      .toPlainString()
));

Shuffle/sort guarantees that one reducer receives all values for a city/category key.

Run

hdfs dfs -put sales.csv /training/input/
hadoop jar retail-revenue-mapreduce-1.0.0.jar \
  /training/input /training/output
hdfs dfs -cat /training/output/part-r-00000
The output directory normally must not exist before the job starts.

8. Equivalent PySpark Solution

result = (
    sales
    .filter(
        (F.col("status") == "COMPLETED")
        & (F.col("quantity") > 0)
        & (F.col("unit_price") >= 0)
        & F.col("discount_pct").between(0, 100)
    )
    .withColumn(
        "net_revenue",
        F.round(
            F.col("quantity") * F.col("unit_price")
            * (F.lit(1) - F.col("discount_pct") / F.lit(100)),
            2
        )
    )
    .groupBy("city", "category")
    .agg(
        F.count("*").alias("order_count"),
        F.sum("quantity").alias("units_sold"),
        F.round(F.sum("net_revenue"), 2).alias("total_revenue")
    )
    .orderBy(F.desc("total_revenue"))
)
result.show(truncate=False)
PySparkMapReduce equivalent
filter and withColumnMapper validation and calculation
groupByMapper key plus shuffle/sort
sumReducer aggregation loop
show/writeTrigger and materialize output
Spark is shorter because the DataFrame API expresses intent; Spark creates physical operators, stages and tasks internally.

10. Pros and Cons

Hadoop / MapReduce Pros

  • Strong HDFS and YARN integration
  • Durable high-throughput batch model
  • Mature in legacy/on-prem estates
  • Predictable map-shuffle-reduce design

Hadoop / MapReduce Cons

  • Verbose code and job configuration
  • Multi-step workflows become difficult
  • Intermediate disk I/O increases latency
  • Poor fit for interactive or iterative work

Spark Pros

  • Concise DataFrame and SQL APIs
  • Good for multi-stage ETL and iterative processing
  • Batch, SQL and streaming use related APIs
  • Runs on YARN, Kubernetes or standalone

Spark Cons

  • Shuffle, memory and skew require expertise
  • Driver misuse can crash jobs
  • Small workloads may not justify overhead
  • Caching everything wastes memory

11. Which Is Best?

For most new analytical processing and ETL: choose Spark.

It usually offers better productivity for DataFrames, SQL, iterative workflows and streaming-oriented use cases.

For distributed storage: HDFS can still be the right choice.

Spark is not an HDFS replacement.

Choose MapReduce when

  • A stable existing Hadoop batch job already meets requirements.
  • Latency is unimportant.
  • The workload is simple and sequential.
  • Migration risk or cost has no clear business return.

Choose Spark when

  • Building new ETL/ELT.
  • Using SQL/DataFrames.
  • Processing has many stages.
  • Doing iterative feature engineering or structured streaming.

Choose both when

  • HDFS stores data.
  • YARN manages resources.
  • Spark performs processing.

14. Best Practices and Migration

MapReduce

  • Use counters for bad records.
  • Use combiners only for safe associative aggregation.
  • Avoid many small HDFS files.
  • Design keys to reduce skew.

Spark

  • Prefer DataFrames and built-ins.
  • Use explicit schemas.
  • Filter/select early.
  • Inspect plans and Spark UI.
  • Avoid unrestricted collect.

Migration Steps

  1. Document mapper, reducer, counters and side effects.
  2. Define exact input/output contracts.
  3. Translate mapper logic to filters and columns.
  4. Translate reducer keys to groupBy and aggregations.
  5. Reconcile counts, rejects and totals.
  6. Compare representative performance.
  7. Run both versions temporarily before cutover.
