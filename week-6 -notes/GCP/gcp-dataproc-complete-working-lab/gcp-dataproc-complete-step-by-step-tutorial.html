1. Tutorial Overview

This tutorial reconciles the supplied Command Prompt transcript and Word document into one clean, executable sequence. Commands that produced errors are excluded from the runnable path.

Source

Windows laptop running Google Cloud CLI.

Storage

Cloud Storage replaces HDFS as durable input and output storage.

Compute

A small single-node Dataproc cluster runs Spark on YARN.

Use Case

Clean food-delivery orders and calculate city revenue.

Verified outcome from the supplied execution: the cluster reached RUNNING, the PySpark job reached DONE, 15 raw rows became 11 clean rows, and the job generated Parquet and CSV outputs.

Learning Objectives

  • Install and validate the Google Cloud CLI on Windows.
  • Understand local CLI configuration versus actual cloud resources.
  • Create a custom service account and assign the correct IAM permissions.
  • Create secure Cloud Storage and networking resources.
  • Understand which Dataproc, Compute Engine, Spark, YARN, and storage services are created.
  • Submit a PySpark job and trace execution from CMD to Cloud Storage output.
  • Delete all chargeable demonstration resources.

2. Corrections Applied to Produce the Working Sequence

The runnable commands in this tutorial intentionally omit failed attempts and retain only corrected patterns.

Issue found in the transcriptCorrection used hereWhy it matters
Project variable used before it was setDefine and echo every variable before useCMD substitutes an empty string for an undefined variable.
Linux-style \ line continuation pasted into CMDUse a single line or the CMD caret ^Backslash is not a Windows CMD continuation character.
File uploaded from the wrong local directorycd /d C:\gcp-dataproc-demo before uploadThe source file must exist relative to the current directory or use an absolute path.
Cluster command omitted the custom subnetInclude --subnet=%SUBNET_NAME%Dataproc otherwise selects another network/subnet and can fail.
Cluster command used the default VM service accountInclude --service-account=%SERVICE_ACCOUNT_EMAIL%The tested bucket access was granted to the custom workload identity.
Custom VPC had no explicit internal ruleCreate dataproc-allow-internalHadoop/Spark nodes need internal TCP, UDP, and ICMP communication.

4. Google Cloud CLI Installation on Windows

Graphical Installer

  1. Open the official Google Cloud CLI installation page.
  2. Download the Windows installer signed by Google LLC.
  3. Launch the installer.
  4. Keep bundled Python selected unless you intentionally manage a supported Python installation.
  5. Allow the installer to add gcloud to PATH.
  6. Open a new Command Prompt after installation.

PowerShell Installer Launch

POWERSHELL
(New-Object Net.WebClient).DownloadFile(
  "https://dl.google.com/dl/cloudsdk/channels/rapid/GoogleCloudSDKInstaller.exe",
  "$env:Temp\GoogleCloudSDKInstaller.exe"
)
& $env:Temp\GoogleCloudSDKInstaller.exe

This PowerShell snippet downloads and launches the official installer. After installation, use CMD for the rest of this lab.

Post-Installation Verification

CMD
gcloud version

What installation creates locally: the gcloud executable, bundled components, optional bundled Python, a user configuration directory, credential files, and PATH entries. It creates no Dataproc cluster and no cloud billing by itself.

Services Inside a Single-Node Cluster

YARN ResourceManager

Accepts the Spark application and schedules containers.

YARN NodeManager

Launches and monitors containers on the VM.

Spark Driver

Builds the execution plan and coordinates stages and tasks.

Spark Executor

Performs CSV reading, filtering, deduplication, aggregation, and writes.

HDFS Services

Installed with the cluster, but this lab keeps durable data in GCS.

Component Gateway

Provides authenticated access paths to supported web interfaces.

6. Every Working Command Explained

The command cards below explain what each command does, what it creates, how it executes, and how to confirm success.

1

Check the Google Cloud CLI version

CMD
gcloud version

What it does

Displays the installed Google Cloud CLI and bundled component versions.

What it creates or changes

No cloud resource. It only reads the local installation information.

How it executes

Windows locates gcloud through PATH and launches the local CLI executable.

Success check

The output displays Google Cloud CLI and component versions.

Trainer note: Run this immediately after installation. If Windows says gcloud is not recognized, reopen Command Prompt or repair PATH.
2

View authenticated accounts

CMD

What it does

Lists Google accounts whose credentials are stored locally and marks the active account.

What it creates or changes

No cloud resource. It reads the local credential store.

How it executes

The CLI reads its local authentication configuration.

Success check

One account has an asterisk in the ACTIVE column.

3

Initialize and authenticate

CMD
gcloud init

What it does

Starts an interactive wizard to authenticate, select a configuration, and choose a default project.

What it creates or changes

Creates or updates a local gcloud configuration profile such as default. It does not create a Dataproc cluster.

How it executes

The CLI opens a browser sign-in flow, stores credentials locally, and writes selected properties to the active configuration.

Success check

The final message says the Google Cloud CLI is configured and ready.

Trainer note: This command was successful in the supplied transcript. Run it once during setup, not before every lab.

PySpark Program: food_delivery_etl.py

PYTHON
import sys

from pyspark.sql import SparkSession
from pyspark.sql import functions as F
from pyspark.sql.types import (
    StructType,
    StructField,
    StringType,
    DoubleType,
)


def main() -> None:
    """Run a small food-delivery ETL job on Dataproc."""

    if len(sys.argv) != 3:
        raise SystemExit(
            "Usage: food_delivery_etl.py <input_csv_gs_uri> <output_base_gs_uri>"
        )

    input_path = sys.argv[1]
    output_base = sys.argv[2].rstrip("/")

    spark = (
        SparkSession.builder
        .appName("GCP-Dataproc-Beginner-ETL")
        .getOrCreate()
    )
    spark.sparkContext.setLogLevel("WARN")

    schema = StructType(
        [
            StructField("order_id", StringType(), True),
            StructField("customer_id", StringType(), True),
            StructField("restaurant_name", StringType(), True),
            StructField("city", StringType(), True),
            StructField("order_status", StringType(), True),
            StructField("order_amount", DoubleType(), True),
            StructField("order_date", StringType(), True),
        ]
    )

    print(f"Reading input from: {input_path}")

    raw_df = (
        spark.read
        .option("header", True)
        .schema(schema)
        .csv(input_path)
    )

    raw_count = raw_df.count()

    clean_df = (
        raw_df
        .withColumn("order_id", F.trim(F.col("order_id")))
        .withColumn("customer_id", F.trim(F.col("customer_id")))
        .withColumn("restaurant_name", F.trim(F.col("restaurant_name")))
        .withColumn("city", F.initcap(F.trim(F.col("city"))))
        .withColumn("order_status", F.upper(F.trim(F.col("order_status"))))
        .withColumn("order_date", F.to_date("order_date", "yyyy-MM-dd"))
        .filter(F.col("order_id").isNotNull())
        .filter(F.length(F.col("order_id")) > 0)
        .filter(F.col("city").isNotNull())
        .filter(F.length(F.col("city")) > 0)
        .filter(F.col("order_amount") > 0)
        .filter(F.col("order_status") == "COMPLETED")
        .dropDuplicates(["order_id"])
    )

    clean_count = clean_df.count()

    city_revenue_df = (
        clean_df
        .groupBy("city")
        .agg(
            F.count("*").alias("completed_orders"),
            F.round(F.sum("order_amount"), 2).alias("total_revenue"),
            F.round(F.avg("order_amount"), 2).alias("average_order_value"),
        )
        .orderBy(F.desc("total_revenue"))
    )

    clean_output = f"{output_base}/clean_orders_parquet"
    revenue_output = f"{output_base}/city_revenue_csv"

    (
        clean_df.write
        .mode("overwrite")
        .parquet(clean_output)
    )

    (
        city_revenue_df
        .coalesce(1)
        .write
        .mode("overwrite")
        .option("header", True)
        .csv(revenue_output)
    )

    print(f"Raw rows:   {raw_count}")
    print(f"Clean rows: {clean_count}")
    print("City revenue result:")
    city_revenue_df.show(truncate=False)
    print(f"Clean Parquet output: {clean_output}")
    print(f"Revenue CSV output:   {revenue_output}")
    print("ETL job completed successfully.")

    spark.stop()


if __name__ == "__main__":
    main()

DataFrame Execution Stages

  1. Read stage: Spark connectors read gs://.../input/orders.csv.
  2. Narrow transformations: trim, upper, initcap, date conversion, and row filters are applied.
  3. Deduplication shuffle: records with the same order ID are brought together.
  4. Aggregation shuffle: completed orders are grouped by city.
  5. Output stage: clean rows are written as Snappy Parquet; city metrics are written as CSV.
  6. Completion: Dataproc marks the job DONE after Spark exits successfully.
Why GCS instead of HDFS? Cluster-local HDFS disappears with an ephemeral cluster. Cloud Storage remains independent of the cluster and is the durable data layer.

11. Cost-Safe Cleanup

Delete resources in dependency order. Start with the Dataproc cluster because its VM and disk are the primary ongoing cost.

CMD
gcloud dataproc clusters delete %CLUSTER_NAME% --region=%REGION% --project=%PROJECT_ID% --quiet
gcloud storage rm --recursive gs://%BUCKET_NAME%/
gcloud compute firewall-rules delete %FIREWALL_RULE% --project=%PROJECT_ID% --quiet
gcloud compute networks subnets delete %SUBNET_NAME% --region=%REGION% --project=%PROJECT_ID% --quiet
gcloud compute networks delete %VPC_NAME% --project=%PROJECT_ID% --quiet
gcloud iam service-accounts delete %SERVICE_ACCOUNT_EMAIL% --project=%PROJECT_ID% --quiet

12. Interview Questions and Answers

1. What is Google Cloud Dataproc?
It is a managed service for running Apache Spark, Hadoop, and related workloads on provisioned clusters or other managed execution models.
2. Why use Cloud Storage rather than HDFS for this lab?
Cloud Storage is durable and independent of the cluster. The cluster can be deleted without deleting the data unless the bucket is explicitly removed.
3. What is the purpose of a Dataproc VM service account?
It is the identity used by the cluster VM and workload when calling Google Cloud APIs and accessing data.
4. Why is Service Account User assigned to the human user?
It contains the ActAs permission needed to deploy a cluster using the selected service account.
5. What does roles/dataproc.worker provide?
It provides permissions needed by the Dataproc VM service account for data-plane cluster operations, including required storage interactions.
6. What does --single-node do?
It places master and worker components on one VM. It is useful for small labs but is not highly available and cannot be converted into a multi-node cluster.
7. Why is --region important?
Dataproc clusters and jobs are regional resources. Commands pointed at another region cannot find them.
8. What is the purpose of --bucket and --temp-bucket?
They select Cloud Storage locations for staging, driver output, temporary files, and related Dataproc artifacts.
9. What does the standalone -- mean in the job command?
It separates gcloud/Dataproc options from arguments passed to the Python driver.
10. What does the YARN ResourceManager do?
It accepts the Spark application and allocates resources for containers.
11. Why use an explicit Spark schema?
It produces predictable types, improves data-quality control, and avoids schema-inference surprises.
12. Why is a shuffle required for groupBy?
Rows with the same grouping key may start in different partitions, so Spark redistributes them before calculating city aggregates.
13. What is the _SUCCESS file?
It is a marker indicating that the Spark output commit completed successfully.
14. Why create an internal firewall rule?
Nodes and distributed services need internal TCP, UDP, and ICMP communication within the subnet.
15. How do you reduce Dataproc lab cost?
Use a small single-node cluster, auto-delete idle settings, short-lived storage, and explicit cleanup immediately after validation.
