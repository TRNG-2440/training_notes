Storage

2. What Is GCP Dataproc?

Definition: Dataproc is Google Cloud's managed environment for running Apache Spark, Hadoop, Hive and related open-source data-processing workloads without manually installing and maintaining every cluster component.

Why use it?

  • Quick cluster creation and deletion.
  • Managed software images and integrations.
  • Direct access to gs:// data through the Cloud Storage connector.
  • Elastic worker sizing and support for temporary clusters.
  • Cloud Logging, Monitoring, IAM and Console integration.

Who uses it?

RoleWhat they do
Data engineerBuilds Spark ETL pipelines and data-lake processing jobs.
Cloud engineerConfigures projects, networks, clusters, images and cost controls.
Platform engineerBuilds reusable cluster templates, policies and automation.
Data analystRuns approved Spark SQL or Hive workloads.
Security administratorDefines IAM roles, service accounts, keys and audit controls.

3. Dataproc Cluster Architecture

Client tools submit a job; the primary node coordinates; worker nodes execute tasks; Cloud Storage contains durable data.

Job journey

  1. A user submits a PySpark file using the Console, CLI, API or scheduler.
  2. Dataproc sends the job to the cluster's primary node.
  3. The Spark Driver builds the DAG and requests resources from YARN.
  4. Executors on worker nodes run tasks against partitions.
  5. Input and output are read from and written to Cloud Storage.
  6. Logs and metrics are available through Google Cloud operations tools.

4. Primary, Worker and Secondary Worker Nodes

NodeMain servicesPurpose
Primary nodeSpark Driver, YARN ResourceManager, HDFS NameNode and management servicesCoordinates applications and cluster resources.
Primary workerSpark Executor, YARN NodeManager, HDFS DataNodeRuns tasks and can hold cluster-local HDFS blocks.
Secondary workerCompute-focused worker, often Spot/preemptibleAdds economical compute capacity; not relied on for durable HDFS data.
Important: The Driver is not the same as the primary node in every deployment model, but in a standard cluster-submitted Spark job the Driver normally runs on the cluster.

5. What Is gcloud dataproc jobs submit pyspark?

Definition: It is the Google Cloud CLI command that submits a Python Spark application to an existing Dataproc cluster.

gcloud dataproc jobs submit pyspark MAIN_FILE.py \
  --cluster=CLUSTER_NAME \
  --region=REGION \
  -- JOB_ARGUMENTS

Meaning of each part

PartMeaning
gcloud dataproc jobs submit pysparkSelects a PySpark job submission.
MAIN_FILE.pyLocal, cluster-local or gs:// Python driver file.
--clusterTarget cluster name.
--regionRegional Dataproc resource namespace.
--Separates gcloud flags from arguments passed to your Python program.
Memory aid: Left of -- belongs to Google Cloud. Right of -- belongs to your PySpark script.

6. Cloud Storage as the HDFS Replacement

Cloud Storage is commonly used as the persistent data-lake layer for Dataproc. The Cloud Storage connector lets Spark and Hadoop applications read and write paths such as gs://bucket/path.

PointHDFSCloud Storage
LocationDisks attached to cluster nodesIndependent Google-managed object storage
LifetimeUsually tied to cluster lifetimeSurvives cluster deletion
ScalingStorage grows by adding disks/nodesStorage scales independently
Pathhdfs:///data/filegs://bucket/data/file
Best useTemporary/local cluster data and some shuffle-adjacent workflowsDurable raw, curated and report data
Precise statement: GCS replaces HDFS for persistent shared storage, but it does not make every HDFS/local-disk function unnecessary. Spark still needs local disks and memory for shuffle, caching and temporary files.

7. Google Cloud Console and CLI

Console

A web interface for learning, visual configuration, job status, IAM inspection, logs and cluster monitoring.

Typical flow: Navigation menu → Dataproc/Managed Spark → Clusters → Create cluster → Jobs → Submit job.

gcloud CLI

A repeatable command interface used for automation, scripts, CI/CD and troubleshooting.

Typical flow: authenticate → set project/region → create resources → submit jobs → inspect → delete.

gcloud auth login
gcloud config set project YOUR_PROJECT_ID
gcloud config set dataproc/region asia-south1

When freshers should use each

  • Use Console first to understand screens and resource relationships.
  • Repeat the same activity with CLI for reproducibility.
  • Use CLI scripts for project demonstrations and team handover.

8. Cloud Storage Buckets

Definition: A bucket is a globally named Cloud Storage container that stores objects such as CSV files, code, logs and Spark output.

Recommended demo layout

gs://YOUR_BUCKET/
├── input/
│   └── retail_orders.csv
├── code/
│   └── retail_sales_dataproc.py
├── output/
│   └── run-20260717-150000/
└── logs/

Create and upload

gcloud storage buckets create gs://YOUR_UNIQUE_BUCKET \
  --location=asia-south1 \
  --uniform-bucket-level-access

gcloud storage cp data/retail_orders.csv \
  gs://YOUR_UNIQUE_BUCKET/input/

gcloud storage cp src/retail_sales_dataproc.py \
  gs://YOUR_UNIQUE_BUCKET/code/
Bucket names are globally unique. “Folders” shown in the Console are object-name prefixes rather than normal operating-system directories.

9. IAM Roles for Data Workloads

Definition: IAM answers three questions: Who is the principal? What role do they have? On which resource?

PrincipalRecommended rolePurpose
Human operatorroles/dataproc.editor or narrowly designed custom roleCreate/update clusters and submit/manage jobs.
Human operator on workload service accountroles/iam.serviceAccountUserAttach/use the service account when creating the cluster.
Workload VM service accountroles/dataproc.workerAllows cluster VMs to operate as Dataproc workers.
Workload service account—inputroles/storage.objectViewerRead and list input objects.
Workload service account—outputroles/storage.objectCreator or roles/storage.objectAdminCreate output; Object Admin also lists/deletes/overwrites objects.
Google-managed service agentroles/dataproc.serviceAgentLets the managed service operate underlying resources. Do not grant to people.
gcloud iam service-accounts create dataproc-retail-worker \
  --display-name="Dataproc retail workload"

gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:dataproc-retail-worker@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/dataproc.worker"

gcloud storage buckets add-iam-policy-binding gs://BUCKET \
  --member="serviceAccount:dataproc-retail-worker@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/storage.objectAdmin"
Production guidance: Grant the smallest role at the smallest resource. The demo uses Object Admin on one training bucket for simplicity; separate input-viewer and output-creator/admin permissions in real projects.

Business requirement

A retailer stores daily orders in Cloud Storage. Management needs total completed revenue by product category. Rows with missing cities, non-positive quantities or discounts outside 0–100 must not enter the report.

A raw GCS object becomes a Pair RDD, is aggregated by category, and is saved back to a new GCS prefix.

12. Setup the Project, APIs, Bucket and Cluster

export PROJECT_ID="YOUR_GCP_PROJECT_ID"
export BUCKET="YOUR_GLOBALLY_UNIQUE_BUCKET"
export REGION="asia-south1"
export CLUSTER="retail-dataproc-demo"
export SA_NAME="dataproc-retail-worker"
export SA_EMAIL="${SA_NAME}@${PROJECT_ID}.iam.gserviceaccount.com"

gcloud auth login
gcloud config set project "${PROJECT_ID}"
gcloud config set dataproc/region "${REGION}"

gcloud services enable \
  dataproc.googleapis.com \
  compute.googleapis.com \
  storage.googleapis.com \
  iam.googleapis.com

Create cluster

gcloud dataproc clusters create "${CLUSTER}" \
  --region="${REGION}" \
  --service-account="${SA_EMAIL}" \
  --scopes="cloud-platform" \
  --master-machine-type="e2-standard-2" \
  --worker-machine-type="e2-standard-2" \
  --num-workers=2 \
  --enable-component-gateway

When a region is provided and a zone is omitted, Dataproc can use auto-zone placement inside that region.

13. PySpark RDD Code Explained

Complete executable program
"""GCP Dataproc PySpark RDD demo."""
from __future__ import annotations
import argparse,csv
from io import StringIO
from typing import Iterator
from pyspark.sql import SparkSession

def parse_args():
    p=argparse.ArgumentParser(description='Dataproc RDD revenue demo')
    p.add_argument('--input',required=True)
    p.add_argument('--output',required=True)
    return p.parse_args()

def parse_csv(line:str)->list[str]:
    return next(csv.reader(StringIO(line)))

def is_valid_completed(v:list[str])->bool:
    try:
        if len(v)!=8: return False
        city=v[2].strip(); category=v[3].strip(); quantity=int(v[4]); price=float(v[5]); discount=float(v[6]); status=v[7].strip().upper()
        return status=='COMPLETED' and bool(city) and bool(category) and quantity>0 and price>=0 and 0<=discount<=100
    except (ValueError,IndexError):
        return False

def to_pair(v:list[str])->tuple[str,float]:
    category=v[3].strip(); quantity=int(v[4]); price=float(v[5]); discount=float(v[6])
    return category, quantity*price*(1-discount/100.0)

def format_partition(index:int, rows:Iterator[tuple[str,float]])->Iterator[str]:
    if index==0: yield 'category,total_completed_revenue'
    for category,revenue in rows: yield f'{category},{revenue:.2f}'

def main():
    args=parse_args()
    spark=SparkSession.builder.appName('GCP-Dataproc-Retail-RDD-Demo').getOrCreate()
    sc=spark.sparkContext; sc.setLogLevel('WARN')
    try:
        raw=sc.textFile(args.input,minPartitions=2)
        header=raw.first()
        report=(raw.filter(lambda line: line.strip() and line!=header)
                  .map(parse_csv)
                  .filter(is_valid_completed)
                  .map(to_pair)
                  .reduceByKey(lambda a,b:a+b)
                  .mapValues(lambda x:round(x,2))
                  .sortBy(lambda x:x[1],ascending=False)
                  .cache())
        print('REPORT PREVIEW')
        for category,revenue in report.collect(): print(f'{category:15s} {revenue:12.2f}')
        report.coalesce(1).mapPartitionsWithIndex(format_partition).saveAsTextFile(args.output.rstrip('/'))
        report.unpersist()
    finally:
        spark.stop()
if __name__=='__main__': main()

Core transformations

CodeWhat it does
sc.textFile(gs_path)Cloud Storage connector loads one RDD element per line.
filter()Removes header/blank lines and invalid/non-completed rows.
map(parse_csv)Turns a CSV string into a Python list.
map(to_pair)Creates (category, net_revenue) Pair RDD records.
reduceByKey()Combines revenue values for identical category keys.
sortBy()Orders categories from highest to lowest revenue.
saveAsTextFile()Writes a GCS output prefix with part files and _SUCCESS.
Why no .master("local[*]")? Dataproc and spark-submit provide YARN/cluster configuration. Forcing local mode would bypass distributed worker execution.

14. Submit and Monitor the PySpark Job

export RUN_ID=$(date +%Y%m%d-%H%M%S)

gcloud dataproc jobs submit pyspark \
  "gs://${BUCKET}/code/retail_sales_dataproc.py" \
  --cluster="${CLUSTER}" \
  --region="${REGION}" \
  -- \
  --input="gs://${BUCKET}/input/retail_orders.csv" \
  --output="gs://${BUCKET}/output/run-${RUN_ID}"

Monitoring commands

gcloud dataproc jobs list --region="${REGION}"
gcloud dataproc jobs describe JOB_ID --region="${REGION}"
gcloud dataproc clusters describe "${CLUSTER}" --region="${REGION}"
gcloud dataproc clusters list --region="${REGION}"
Output rule: Spark output paths must be new. Use a timestamped run-ID or delete the previous prefix before rerunning.

15. Verify Output and Delete the Cluster

gcloud storage ls "gs://${BUCKET}/output/run-${RUN_ID}/"
gcloud storage cat "gs://${BUCKET}/output/run-${RUN_ID}/part-00000"

gcloud dataproc clusters delete "${CLUSTER}" \
  --region="${REGION}" \
  --quiet

Expected objects

gs://BUCKET/output/run-ID/
├── part-00000
└── _SUCCESS
Cost rule: A running cluster uses billable Compute Engine resources even when no job is running. Delete temporary training clusters immediately after verification.

16. Best Practices and Troubleshooting

ProblemLikely causeFix
PERMISSION_DENIED reading GCSVM service account lacks object viewer/admin.Grant the role on the bucket and confirm cluster uses that service account.
Cannot attach service accountHuman lacks Service Account User.Grant roles/iam.serviceAccountUser on the workload account.
Output already existsReused Spark output prefix.Use a unique run ID or remove the old prefix.
Cluster created in wrong projectgcloud project not configured.Run gcloud config get-value project.
Job cannot find clusterRegion mismatch.Use the same region for create, submit, describe and delete.
Python argument missingForgot the -- separator.Place job arguments after --.
Unexpected high costCluster left running.Delete it and use labels/automation/idle deletion policies.

Industry practices

  • Keep durable data in GCS, not only cluster-local HDFS.
  • Use a user-managed service account instead of broad default permissions.
  • Separate raw, clean, curated and report prefixes.
  • Keep bucket and cluster in compatible locations to reduce latency and network cost.
  • Use temporary clusters for batch jobs when startup time is acceptable.
  • Capture job IDs, row counts, output paths and failure reasons in a runbook.
