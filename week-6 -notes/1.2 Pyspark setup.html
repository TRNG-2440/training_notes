Spark Setup with PySpark

Install, configure, verify, troubleshoot, and run your first end-to-end PySpark application using a clean, reproducible environment.

PySpark 4.1.2 Python 3.10+ Java 17 or 21 Windows • Linux • macOS Hands-on lab

1. Setup Overview and Learning Outcomes

PySpark is the Python API for Apache Spark. Your Python program defines transformations, while Spark's JVM-based engine plans and executes the work.

Recommended route: Install a supported JDK, install Python, create a virtual environment, and install PySpark with pip. This route does not normally require a separate Spark download or SPARK_HOME.
Install

Java, Python, virtual environment, PySpark.

Verify

Check versions, start SparkSession, execute a DataFrame action.

Apply

Build a small retail-sales transformation and aggregation.

By the end, you can

  • Explain why Java is required for standard PySpark.
  • Configure JAVA_HOME correctly.
  • Run PySpark from PowerShell, Terminal, VS Code, and Jupyter.
  • Interpret driver, executor, job, stage, task, and partition at setup level.
  • Diagnose common gateway, PATH, Python-worker, and port errors.
Memory aid — J-P-V-S: Java → Python → Virtual environment → Spark verification.

  2. PySpark starts or connects to the JVM-side Spark driver.

8. Your First Structured PySpark Application

Create employee_analysis.py:

from pyspark.sql import SparkSession
from pyspark.sql.functions import avg, col, desc

def main() -> None:
    spark = (
        SparkSession.builder
        .appName("EmployeeDepartmentAnalysis")
        .master("local[*]")
        .config("spark.sql.shuffle.partitions", "4")
        .getOrCreate()
    )

    spark.sparkContext.setLogLevel("WARN")

    employees = [
        (101, "Anu", "Data", 72000),
        (102, "Bala", "Data", 68000),
        (103, "Charan", "Cloud", 80000),
        (104, "Divya", "Cloud", 76000),
        (105, "Esha", "QA", 61000),
    ]

    df = spark.createDataFrame(
        employees,
        ["employee_id", "name", "department", "salary"]
    )

    print("=== Source Data ===")
    df.show()

    print("=== Employees earning at least 70,000 ===")
    df.filter(col("salary") >= 70000).show()

    print("=== Average salary by department ===")
    (
        df.groupBy("department")
        .agg(avg("salary").alias("average_salary"))
        .orderBy(desc("average_salary"))
        .show()
    )

    spark.stop()

if __name__ == "__main__":
    main()

Run it

python employee_analysis.py

# Or use Spark's launcher
spark-submit --master "local[*]" employee_analysis.py

10. Practical Lab — Retail Sales Setup Validation

Requirement

A retail team wants to validate a fresh PySpark workstation. The program must calculate line revenue, filter completed orders, summarize revenue by category, and show the highest-revenue category.

Expected result

  • Only COMPLETE transactions are included.
  • line_revenue = quantity × unit_price.
  • Revenue is grouped by category and sorted descending.

Implementation

from pyspark.sql import SparkSession
from pyspark.sql.functions import col, round, sum as spark_sum

spark = (
    SparkSession.builder
    .appName("RetailSalesSetupValidation")
    .master("local[*]")
    .config("spark.sql.shuffle.partitions", "4")
    .getOrCreate()
)

spark.sparkContext.setLogLevel("WARN")

sales = [
    ("O1001", "Laptop", "Electronics", 1, 72000.0, "COMPLETE"),
    ("O1002", "Mouse", "Electronics", 3, 850.0, "COMPLETE"),
    ("O1003", "Chair", "Furniture", 2, 6500.0, "CANCELLED"),
    ("O1004", "Desk", "Furniture", 1, 11000.0, "COMPLETE"),
    ("O1005", "Notebook", "Stationery", 10, 75.0, "COMPLETE"),
    ("O1006", "Pen Pack", "Stationery", 4, 120.0, "COMPLETE"),
]

columns = [
    "order_id", "product", "category",
    "quantity", "unit_price", "status"
]

df = spark.createDataFrame(sales, columns)

completed = (
    df.filter(col("status") == "COMPLETE")
      .withColumn(
          "line_revenue",
          round(col("quantity") * col("unit_price"), 2)
      )
)

summary = (
    completed.groupBy("category")
    .agg(round(spark_sum("line_revenue"), 2).alias("revenue"))
    .orderBy(col("revenue").desc())
)

completed.show(truncate=False)
summary.show(truncate=False)

top_category = summary.first()
print(
    f"Top category: {top_category['category']} "
    f"with revenue {top_category['revenue']}"
)

spark.stop()

Expected summary

CategoryRevenue
Electronics74,550.00
Furniture11,000.00
Stationery1,230.00

Exercises

  1. Add an order date and calculate monthly revenue.
  2. Add a 5% discount for quantities of five or more.
  3. Write the summary as CSV with coalesce(1) only for this small lab.
  4. Use explain("formatted") to inspect the physical plan.
  5. Change local[*] to local[2] and compare the UI.

Conclusion

If this lab runs successfully, the Java gateway, Python environment, SparkSession, DataFrame API, transformations, actions, and local task execution are all working.

11. Best Practices, Edge Cases, and Project Structure

Pin versions

Use requirements.txt or a modern project configuration so all learners install the same packages.

One environment per project

Do not install every data tool into the global Python interpreter.

Keep data outside .venv

Virtual environments are disposable. Project code and data belong in normal project folders.

Stop the session

Use try/finally for applications that must always release Spark resources.

Safer session pattern

from pyspark.sql import SparkSession

spark = None

try:
    spark = (
        SparkSession.builder
        .appName("SafeApplication")
        .master("local[2]")
        .getOrCreate()
    )
    spark.range(5).show()
finally:
    if spark is not None:
        spark.stop()

Edge cases

  • Multiple Python installations: use python -m pip and inspect sys.executable.
  • Corporate proxy: package downloads may need approved proxy/certificate configuration.
  • OneDrive/network folders: move shuffle/temp-heavy projects to a short local path if file locking occurs.
  • Low disk space: clear old temporary output and unused virtual environments; do not delete active project data blindly.
  • Large local collect: use show(), take(), or limited aggregations rather than retrieving all rows.

20 Interview Questions with Answers

1. What is PySpark?

PySpark is Apache Spark's Python API. It lets Python applications use Spark's distributed execution engine for SQL, DataFrames, streaming, machine learning, and RDD workloads.

2. Why does PySpark need Java?

Spark's core engine runs on the JVM. Standard PySpark uses Py4J so Python driver code can communicate with JVM objects and submit work to Spark.

3. What is Py4J?

Py4J is the bridge used by standard PySpark to let Python code interact with Java objects inside the JVM.

4. What is SparkSession?

SparkSession is the primary entry point for DataFrame and SQL operations. It also provides access to the underlying SparkContext.

5. SparkContext versus SparkSession?

SparkContext represents the connection to Spark's execution environment and is central to RDD functionality. SparkSession is the higher-level entry point used for DataFrames, SQL, and modern applications.

6. What does local[*] mean?

It runs Spark in local mode and allows Spark to use all available logical CPU cores. For controlled classroom demos, local[2] is sometimes easier to observe.

7. Is SPARK_HOME required after pip install pyspark?

For the normal pip-only local setup, it is usually not required because the package contains the needed Spark distribution. It is needed when you manually download and manage Spark.

8. Why use a virtual environment?

It isolates PySpark and other project dependencies, prevents package conflicts, and makes the environment easier to reproduce.

9. What is lazy evaluation?

Spark records transformations as a logical plan. It executes the plan only after an action such as show, count, collect, or write is called.

10. Transformation versus action?

A transformation creates a new logical dataset, while an action triggers execution and returns or writes a result.

11. What is a partition?

A partition is a logical chunk of a distributed dataset. Spark schedules tasks per partition, so partitioning influences parallelism and performance.

12. Driver versus executor?

The driver builds the execution plan and coordinates the application. Executors run tasks and hold cached or shuffled data. In local mode they run within the local Spark process arrangement.

13. What does spark-submit do?

It launches a Spark application with Spark-specific configuration, dependencies, master settings, and deployment options.

14. What is the Spark UI?

It is a diagnostic web interface showing jobs, stages, tasks, SQL plans, storage, environment settings, and executors. A local application commonly starts at port 4040.

15. Why avoid collect() on large data?

collect() transfers the entire result to driver memory. If the result is large, the driver can run out of memory.

16. How do you reduce Spark console logs?

Use spark.sparkContext.setLogLevel('WARN') or configure Log4j more formally for project environments.

17. What causes JAVA_GATEWAY_EXITED?

Typical causes include missing Java, an unsupported Java version, incorrect JAVA_HOME, a damaged PATH, security software interference, or a port/process startup failure.

18. How do you confirm the runtime versions?

Check python --version, java -version, python -m pip show pyspark, and print spark.version from a running SparkSession.

19. Can PySpark run without Hadoop installed?

Yes for local files and many local/cloud workloads. Hadoop client libraries are bundled with common Spark distributions, but a Hadoop cluster is needed when you want to use HDFS/YARN services.

20. Why stop SparkSession?

Stopping releases resources, closes the SparkContext, and prevents background Spark processes from remaining after the application completes.
