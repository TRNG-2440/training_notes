End-to-End DataOps & CI/CD Tutorial

A trainer-ready tutorial that starts with the problem, introduces DataOps practices, and finishes with a practical Snowflake + dbt + Airflow pipeline where GitHub Actions automatically tests pull requests before deployment.

2. Story: Why DataOps?

FreshCart Sales Analytics

FreshCart receives sales transactions every day. Analysts need a clean daily sales summary in Snowflake. Three people work on the pipeline:

  • Data Engineer: loads raw sales data.
  • Analytics Engineer: creates dbt transformations.
  • Platform Engineer: schedules jobs in Airflow.

Without DataOps, one engineer edits SQL directly in production, another changes the Airflow DAG independently, and nobody knows whether a broken transformation was tested before release. A small SQL typo or null key can break dashboards.

3. DataOps Lifecycle

DataOps applies DevOps-style collaboration, automation, quality control, observability, and continuous improvement to data pipelines.

4. DataOps Key Practices

Collaboration

Use Git branches, pull requests, reviews, naming conventions, ownership, and shared documentation.

Goal: no silent direct changes to production.

Automation

Automate model builds, tests, DAG validation, and deployment.

Goal: repeatable execution rather than manual copying.

Monitoring

Track task state, logs, data tests, runtime, freshness, and failures.

Goal: detect problems before business users do.

Trainer phrase: “DataOps is not one tool. It is a working model: people + process + automation + quality + observability.”

11. Step 3 — Airflow Orchestration

Airflow controls when the workflow runs and in what order. dbt controls transformation logic inside Snowflake.

Simple DAG using BashOperator

# airflow/dags/freshcart_dbt_pipeline.py
from datetime import datetime
from airflow import DAG
from airflow.providers.standard.operators.bash import BashOperator

DBT_DIR = "/opt/airflow/dbt_freshcart"

with DAG(
    dag_id="freshcart_dbt_pipeline",
    start_date=datetime(2026, 1, 1),
    schedule="@daily",
    catchup=False,
    tags=["dataops", "dbt", "snowflake"],
) as dag:

    dbt_debug = BashOperator(
        task_id="dbt_debug",
        bash_command=f"cd {DBT_DIR} && dbt debug --target prod",
    )

    dbt_build = BashOperator(
        task_id="dbt_build",
        bash_command=f"cd {DBT_DIR} && dbt build --target prod",
    )

    dbt_debug >> dbt_build
Airflow version note: operator import paths vary by Airflow/provider version. For older Airflow 2.x installs you may see from airflow.operators.bash import BashOperator. Use the import matching your installed version.

What to show students in Airflow UI

  1. DAG list → locate freshcart_dbt_pipeline.
  2. Open Graph view.
  3. Explain dependency: dbt_debug → dbt_build.
  4. Trigger DAG manually.
  5. Open each task → Logs.
  6. Show dbt test results inside the Airflow task log.

13. Step 5 — GitHub Actions CI Pipeline

GitHub Actions can run automated checks whenever a pull request targets main.

Add GitHub repository secrets

GitHub → Repository → Settings → Secrets and variables → Actions → New repository secret.

SecretValue
SNOWFLAKE_ACCOUNTYour account identifier
SNOWFLAKE_USERCI service user
SNOWFLAKE_PASSWORDPassword for the training demo
SNOWFLAKE_ROLERole with limited CI privileges
Production practice: prefer short-lived/key-pair/OIDC-style authentication where supported instead of long-lived passwords. Snowflake’s current CI/CD guidance includes secure CI/CD options such as OIDC for supported workflows.

Create .github/workflows/ci.yml

name: FreshCart CI

on:
  pull_request:
    branches: [ main ]

jobs:
  dbt-ci:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install dbt-snowflake pytest

      - name: Create dbt profile
        run: |
          mkdir -p ~/.dbt
          cat > ~/.dbt/profiles.yml <<'EOF'
          dbt_freshcart:
            target: ci
            outputs:
              ci:
                type: snowflake
                account: ${{ secrets.SNOWFLAKE_ACCOUNT }}
                user: ${{ secrets.SNOWFLAKE_USER }}
                password: ${{ secrets.SNOWFLAKE_PASSWORD }}
                role: ${{ secrets.SNOWFLAKE_ROLE }}
                database: FRESHCART
                warehouse: DATAOPS_WH
                schema: CI
                threads: 2
          EOF

      - name: dbt debug
        working-directory: dbt_freshcart
        run: dbt debug --target ci

      - name: dbt parse
        working-directory: dbt_freshcart
        run: dbt parse

      - name: dbt build
        working-directory: dbt_freshcart
        run: dbt build --target ci

      - name: Python tests
        run: pytest -q

What happens now?

PR opened
   │
   ▼
GitHub runner starts
   │
   ├─ checkout source
   ├─ install Python/dbt/pytest
   ├─ create runtime-only profile
   ├─ dbt debug
   ├─ dbt parse
   ├─ dbt build --target ci
   └─ pytest
        │
        ├── any failure → red X → DO NOT MERGE
        └── all pass    → green ✓ → review + merge

Optional Airflow DAG import test

# airflow/tests/test_dag_import.py
from airflow.models import DagBag

def test_dags_have_no_import_errors():
    dag_bag = DagBag(dag_folder="airflow/dags", include_examples=False)
    assert dag_bag.import_errors == {}

def test_expected_dag_exists():
    dag_bag = DagBag(dag_folder="airflow/dags", include_examples=False)
    assert "freshcart_dbt_pipeline" in dag_bag.dags

If CI installs Airflow and the required provider, this test catches broken DAG imports before deployment.

14. Step 6 — Simple CD Pipeline

For teaching, deploy the dbt project after a merge to main. In a production environment, add approvals and stronger authentication.

.github/workflows/deploy.yml

name: FreshCart Deploy

on:
  push:
    branches: [ main ]

jobs:
  deploy-dbt:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install dbt
        run: pip install dbt-snowflake

      - name: Create production dbt profile
        run: |
          mkdir -p ~/.dbt
          cat > ~/.dbt/profiles.yml <<'EOF'
          dbt_freshcart:
            target: prod
            outputs:
              prod:
                type: snowflake
                account: ${{ secrets.SNOWFLAKE_ACCOUNT }}
                user: ${{ secrets.SNOWFLAKE_USER }}
                password: ${{ secrets.SNOWFLAKE_PASSWORD }}
                role: ${{ secrets.SNOWFLAKE_ROLE }}
                database: FRESHCART
                warehouse: DATAOPS_WH
                schema: PROD
                threads: 2
          EOF

      - name: Deploy transformations
        working-directory: dbt_freshcart
        run: dbt build --target prod
Trainer distinction: Running dbt build --target prod after merge is a basic classroom CD pattern. In enterprise projects, “deployment” may instead publish a dbt project/job definition, promote artifacts, use a managed dbt platform, use Snowflake dbt project objects, or trigger a separate orchestrator.

16. The Most Important Demo — Make CI Fail

Students understand CI/CD much faster when they see a pull request get blocked.

Introduce bad source data

VALUES (6,104,'Headset',-2500,'2026-08-04');

The custom test:

select *
from {{ ref('stg_sales') }}
where amount <= 0

Now rerun:

dbt test --target ci
Expected: assert_positive_amount fails because the negative amount appears in the result set.

Explain the DataOps value

Bad data enters RAW
      │
      ▼
dbt transformation
      │
      ▼
Automated test detects amount <= 0
      │
      ▼
CI returns FAILURE
      │
      ▼
PR stays unmergeable (when branch protection requires the check)
      │
      ▼
Engineer fixes data logic / source issue
      │
      ▼
Push new commit → CI reruns → PASS

18. Troubleshooting

dbt says profile not found

Verify %USERPROFILE%\.dbt\profiles.yml on Windows or ~/.dbt/profiles.yml on Linux. Ensure the top-level profile name matches profile: in dbt_project.yml.

Snowflake authentication fails in GitHub Actions

Check repository secrets, account identifier format, role, warehouse/database privileges, and whether the CI user is allowed to authenticate from the runner.

dbt test fails unexpectedly

Run the generated failing SQL or inspect the test result. Remember: a singular dbt data test generally fails when it returns rows.

Airflow DAG does not appear

Check DAG import errors, the DAG folder, Python syntax, provider imports, and scheduler health. DAG import tests in CI help catch this earlier.

GitHub Actions is not running

Verify that the workflow YAML is under .github/workflows/ and that the trigger matches the PR target branch or push branch.

CI and PROD overwrite each other

Never point both targets at the same schema. Use an isolated CI schema (or per-PR schemas in a more advanced design) and a separate PROD schema.

19. Interview Questions & Answers

1. What is DataOps?

DataOps is a set of collaborative and automated practices for developing, testing, deploying, orchestrating, and monitoring reliable data products and pipelines.

2. Is DataOps a tool?

No. It is an operating practice supported by tools such as Git, CI/CD systems, dbt, Airflow, cloud warehouses, tests, and observability platforms.

3. What is CI in a dbt project?

CI automatically validates proposed transformation changes, typically on a pull request, using commands such as parsing, compiling, building, and testing against an isolated environment.

4. What is CD?

CD promotes validated changes to higher environments after integration, either automatically or after approval.

5. Why use separate DEV, CI, and PROD schemas?

They isolate developer experimentation, automated PR validation, and production data so changes do not overwrite one another.

6. Why is dbt useful in DataOps?

dbt brings modular SQL, dependency management, tests, documentation, lineage concepts, and repeatable execution into analytics engineering workflows.

7. What does Airflow add if dbt can run models?

dbt handles transformation logic and dependencies among dbt resources. Airflow orchestrates broader workflows, schedules, retries, upstream/downstream systems, and operational execution.

8. What is a pull request quality gate?

A required automated check that must pass before a branch can be merged, often combined with human code review.

9. What does a dbt not_null test validate?

It verifies that the tested column contains no null values in the model output.

10. What does a dbt unique test validate?

It checks that values in the selected column are unique.

11. What is a singular dbt test?

A custom SQL query written so that rows returned represent failures. Zero returned rows means the rule passed.

12. What is an Airflow DAG import test?

A test that loads DAG definitions and verifies there are no Python/import errors and expected DAG IDs exist.

13. Why should secrets not be stored in Git?

Git history is durable and often shared. Credentials should be stored in secret managers or CI secret stores and injected at runtime.

14. What is the benefit of branch protection?

It can prevent direct pushes or merges until required reviews and CI checks pass.

15. What should we monitor besides pipeline task success?

Data freshness, volume, nulls, uniqueness, business-rule validity, runtime trends, warehouse consumption, retries, and SLA violations.

16. What is idempotency in a data pipeline?

Running the same operation repeatedly should not unintentionally duplicate or corrupt results. Idempotent tasks are safer to retry.

17. Why automate tests in CI instead of relying on local tests?

CI provides a consistent, repeatable validation environment and makes the result visible to the whole team before merge.

18. CI passed, but production failed. What could cause this?

Environment differences, permissions, larger data volumes, missing secrets, different configurations, runtime dependencies, or tests that did not cover the production scenario.

19. How can a team improve this demo for enterprise use?

Add isolated per-PR schemas, least-privilege service identities, OIDC/key-pair authentication, environment approvals, artifact promotion, alerting, data contracts, freshness checks, and rollback procedures.

20. What is the difference between orchestration and transformation?

Orchestration controls workflow scheduling and task dependencies across systems. Transformation changes data from one representation to another, such as raw sales to aggregated customer metrics.
