1. What are these concepts?

BigQuery Python client

The google-cloud-bigquery Python library lets a Python application communicate with Google BigQuery programmatically. Instead of manually opening the BigQuery console and running SQL, your code can submit SQL, wait for the query job, and load the result into Python objects or a Pandas DataFrame.

Without Python clientWith Python client
User opens BigQuery Console and manually executes SQL.Streamlit/Python runs the SQL automatically when the application needs data.
Good for ad-hoc analysis.Good for applications, dashboards, automation and APIs.

Caching BigQuery in Streamlit

Streamlit reruns your Python script when users interact with widgets. If every rerun sends the same query to BigQuery, the dashboard can become slower and can repeatedly consume query resources. @st.cache_data stores the returned data for a period of time and reuses it when the same function is called with the same inputs.

Purpose: improve responsiveness and reduce unnecessary repeated BigQuery calls. A common training example is @st.cache_data(ttl=600), which caches results for 10 minutes.

Service authentication in Streamlit Cloud

Your deployed app needs an identity to access BigQuery. A service account is a non-human Google Cloud identity intended for applications and workloads. In Streamlit Community Cloud, the credentials should be stored in Streamlit's Secrets area, not committed to GitHub.

Security rule: never upload a downloaded service-account JSON key to a public GitHub repository. Treat the private key like a password.

7. BigQuery Python Client — Core Code

The central object is bigquery.Client. It sends SQL to BigQuery using the credentials associated with the client.

from google.cloud import bigquery

client = bigquery.Client()

query = '''
SELECT category, SUM(amount) AS revenue
FROM `YOUR_PROJECT_ID.freshcart_demo.sales_orders`
GROUP BY category
ORDER BY revenue DESC
'''

df = client.query(query).to_dataframe()
print(df)

What happens internally?

  1. Python creates a BigQuery client.
  2. client.query() creates a BigQuery query job.
  3. BigQuery executes SQL in Google Cloud.
  4. to_dataframe() converts returned rows to a Pandas DataFrame.
  5. Streamlit can render the DataFrame as a table or chart.

8. Caching BigQuery Results in Streamlit

8.1 Why caching matters

Clicking a Streamlit widget normally reruns the Python script from top to bottom. Without caching, a filter, checkbox or button can cause the same expensive data query to be executed again.

SituationNo cacheWith cache
User reruns app 5 timesPotentially 5 BigQuery query executionsUsually 1 execution until TTL expires
Response timeWait for BigQuery repeatedlyCached result returns quickly
FreshnessLatest dataUp to TTL old

8.2 Recommended pattern

@st.cache_data(ttl=600, show_spinner="Loading data from BigQuery...")
def run_query(query: str):
    return client.query(query).to_dataframe()

ttl=600 means the cached entry can be reused for 600 seconds (10 minutes).

Trainer point: caching is a trade-off. Short TTL = fresher data but more queries. Long TTL = fewer queries but potentially older data.

8.3 Manual cache clear

if st.button("Refresh now"):
    st.cache_data.clear()
    st.rerun()

This gives the user a way to force fresh data before the TTL expires.

9. Create Service Authentication for Streamlit Cloud

9.1 What is a service account?

A service account represents the application rather than a person. Streamlit Cloud uses its credentials to prove “this deployed app is allowed to query these BigQuery resources”.

9.2 Create the service account — where to click

Google Cloud Console → IAM & Admin → Service Accounts.
Click Create service account.
Name: streamlit-bigquery-demo.
Click Create and continue.
Grant only the roles required for this demo.

9.3 Roles for the demo

RoleWhy
BigQuery Job UserAllows the service account to create/query BigQuery jobs.
BigQuery Data ViewerAllows read access to the table/dataset. Prefer granting this at the dataset level when possible.
Production guidance: avoid Owner/Editor for an application identity. Use least privilege.

9.4 Create a JSON key for this Streamlit Community Cloud lab

Open the service account.
Click the Keys tab.
Add key → Create new key.
Choose JSON → Create.
The browser downloads the JSON credential file. Store it securely and do not commit it.
Important: long-lived JSON service-account keys are convenient for training, but keyless/workload-identity approaches are preferable when the hosting platform supports them. For this Community Cloud demonstration, we place the JSON fields into Streamlit Secrets instead of GitHub.

Your .streamlit/secrets.toml should look like this:

10. Complete Streamlit Application + Community Cloud Deployment

10.1 app.py

import streamlit as st
from google.cloud import bigquery
from google.oauth2 import service_account

st.set_page_config(page_title="FreshCart Sales", layout="wide")
st.title("FreshCart Sales Dashboard")

PROJECT_ID = st.secrets["gcp_service_account"]["project_id"]

@st.cache_resource
def get_bigquery_client():
    credentials = service_account.Credentials.from_service_account_info(
        dict(st.secrets["gcp_service_account"])
    )
    return bigquery.Client(
        credentials=credentials,
        project=PROJECT_ID
    )

client = get_bigquery_client()

@st.cache_data(ttl=600, show_spinner="Loading BigQuery data...")
def run_query(query: str):
    return client.query(query).to_dataframe()

summary_sql = f'''
SELECT
    COUNT(*) AS order_count,
    SUM(amount) AS total_revenue,
    AVG(amount) AS avg_order_value
FROM `{PROJECT_ID}.freshcart_demo.sales_orders`
'''

category_sql = f'''
SELECT
    category,
    SUM(amount) AS revenue
FROM `{PROJECT_ID}.freshcart_demo.sales_orders`
GROUP BY category
ORDER BY revenue DESC
'''

orders_sql = f'''
SELECT *
FROM `{PROJECT_ID}.freshcart_demo.sales_orders`
ORDER BY order_date DESC, order_id DESC
'''

summary = run_query(summary_sql).iloc[0]
category_df = run_query(category_sql)
orders_df = run_query(orders_sql)

c1, c2, c3 = st.columns(3)
c1.metric("Orders", int(summary["order_count"]))
c2.metric("Total Revenue", f'${summary["total_revenue"]:,.2f}')
c3.metric("Average Order Value", f'${summary["avg_order_value"]:,.2f}')

st.subheader("Revenue by Category")
st.bar_chart(category_df.set_index("category"))

st.subheader("Orders")
st.dataframe(orders_df, use_container_width=True)

if st.button("Refresh BigQuery Data"):
    st.cache_data.clear()
    st.rerun()

st.caption("BigQuery results are cached for 10 minutes.")

11. How to Showcase This to Trainees

Use this 10–15 minute demonstration sequence:

  1. BigQuery console: show the table and run a simple SELECT *.
  2. Python client: explain that the dashboard does the same query programmatically.
  3. Run Streamlit: show metrics and chart.
  4. Explain Streamlit reruns: every widget interaction can rerun the script.
  5. Show cache: point to @st.cache_data(ttl=600). Explain “the data result is reused for 10 minutes”.
  6. Show service identity: open Google Cloud → IAM & Admin → Service Accounts.
  7. Show secrets: open Streamlit Cloud → app settings/Advanced settings → Secrets. Do not expose the actual private key on a projector.
  8. Refresh: use the refresh button to clear cache and force a new BigQuery query.
Best live experiment: add one row to BigQuery after the dashboard has loaded. Rerun the Streamlit UI and show that the cached value may remain unchanged. Then click Refresh BigQuery Data and show the new total. This makes caching easy to understand.

Optional SQL to add one new row

INSERT INTO `YOUR_PROJECT_ID.freshcart_demo.sales_orders`
(order_id, order_date, category, quantity, amount)
VALUES
(1007, CURRENT_DATE(), 'Laptop', 1, 1000.00);

13. Review / Interview Questions

  1. What is the BigQuery Python client?
    A Google Cloud client library used by Python applications to submit queries and interact with BigQuery programmatically.
  2. Why use st.cache_data?
    To reuse data results across reruns, improving response time and avoiding unnecessary repeated computation or database calls.
  3. What does TTL mean?
    Time to live: how long a cache entry is valid before it is recomputed.
  4. What is a service account?
    A workload/application identity in Google Cloud, rather than an individual user's identity.
  5. Why not put service-account JSON in GitHub?
    It contains a private credential that can be abused to access cloud resources.
  6. Difference between st.cache_data and st.cache_resource?
    st.cache_data is primarily for serializable data results such as DataFrames. st.cache_resource is for shared resources such as clients/connections/models.
  7. What permissions does this demo need?
    The application must be able to run BigQuery jobs and read the required data; a common least-privilege combination is BigQuery Job User plus BigQuery Data Viewer scoped appropriately.
