Learning outcomes

What trainees will understand

Accuracy

Is the value factually/business-correct?

Completeness

Are required values present?

Timeliness

Did the data arrive within the required time?

Consistency

Is the same fact represented uniformly across records/systems?

Memory trick: Correct? → Accuracy. Missing? → Completeness. Late? → Timeliness. Different representation? → Consistency.
Concept story

FreshCart's morning dashboard problem

FreshCart's manager opens the 9 AM order dashboard and sees ₹10 lakh in sales. The report looks professional—but four hidden data-quality problems make it unreliable.

Problem A — Wrong amount

An order is stored as -250, even though business rules say order value must be positive.

Dimension: Accuracy.

Problem B — Missing customer

One order has no customer_id.

Dimension: Completeness.

Problem C — Data arrived 3 days late

An order happened on Aug 15 but was loaded on Aug 18.

Dimension: Timeliness.

Problem D — Multiple codes for same meaning

Country appears as India and IND; status appears as DELIVERED and Delivered.

Dimension: Consistency.

Trainer question: “If there are no nulls, can the data still be poor quality?” The answer is yes—accuracy, timeliness and consistency can fail even when every column is populated.

Theory

The four dimensions in one table

DimensionCore questionTypical checkExample failureTypical remediation
AccuracyIs it correct?Range/reference/business ruleorder_amount = -250Validate against source/reference; reject or quarantine
CompletenessIs required data present?NOT NULL / completeness %customer_id is nullMake field mandatory; backfill
TimelinessIs it fresh enough?arrival delay / latest timestamploaded 3 days after orderFix pipeline SLA / alert on delay
ConsistencyIs it represented the same way?allowed values / cross-field/system matchIndia vs INDStandardize canonical values

Simple formulas

Completeness % = (Non-null required values / Total expected values) × 100

Timeliness delay = loaded_at - order_date

Consistency % = (Rows following the standard / Total rows) × 100

Accuracy % = (Rows verified as correct / Rows checked) × 100
Important: Accuracy usually needs a trusted reference or business rule. A value can be syntactically valid but still factually wrong.

Dimension 1

Accuracy — “Is the value correct?”

For our business, a completed order must have order_amount > 0. The value -250 is therefore inaccurate.

GUI rule idea

In the Data Quality Scan, add a range/validity rule if the UI offers the needed comparison. Otherwise use a custom SQL expression rule such as:

order_amount > 0
Add data quality rule — Accuracy
Column: order_amount
Rule type: Range / Custom SQL expression
Condition: order_amount > 0
Dimension: Accuracy
Threshold: 100%
Expected failure: O1004 because order_amount = -250.

Teaching point: Accuracy is contextual. “250” may be a valid numeric value, but if the source says 1250 or the business rule forbids negatives, it is inaccurate.

Dimension 2

Completeness — “Is required data present?”

The business requires every order to be linked to a customer. Therefore customer_id must not be null.

GUI rule

Add a non-null / completeness rule on customer_id and set the threshold to 100%.

Add data quality rule — Completeness
Column: customer_id
Rule type: Non-null / Completeness
Threshold: 100%
Dimension: Completeness
Expected failure: O1003 has a missing customer_id.

There are 8 rows and 7 populated customer IDs:

Completeness = 7 / 8 × 100 = 87.5%
Ask students: If the threshold is 95%, does the rule pass? No—87.5% is below 95%.
Dimension 3

Timeliness — “Did the data arrive within the SLA?”

FreshCart's SLA says an order should be loaded into analytics within 60 minutes of the order time.

O1006 occurred on Aug 15 but was loaded on Aug 18, so it is far outside the SLA.

GUI approach

Use a custom SQL expression/row condition comparing order_date and loaded_at. A BigQuery-style expression is:

TIMESTAMP_DIFF(loaded_at, order_date, MINUTE) <= 60
Add data quality rule — Timeliness
Rule type: Custom SQL expression
Expression: TIMESTAMP_DIFF(loaded_at, order_date, MINUTE) <= 60
Dimension: Timeliness
Threshold: 100%
Expected failure: O1006. The other sample rows are loaded within minutes.
Key distinction: Timeliness is not “does the date exist?” That would be completeness. Timeliness measures whether the data is fresh/available within the required time window.
Dimension 4

Consistency — “Are values represented uniformly?”

Suppose the standard country value is India and allowed statuses are exactly SHIPPED or DELIVERED.

Country consistency rule

country = 'India'

Status consistency rule

order_status IN ('SHIPPED','DELIVERED')
Country failure: O1005 contains IND.
Status failure: O1007 contains Delivered instead of the agreed canonical value DELIVERED.

Why this matters: A dashboard grouping by status can accidentally produce separate categories for DELIVERED and Delivered.

Remediation

Part C — Fix the records and re-run

Use the BigQuery editor to create a corrected copy for demonstration. This keeps the original “bad” table available for comparison.

CREATE OR REPLACE TABLE `YOUR_PROJECT_ID.dq_demo.customer_orders_clean` AS
SELECT
  order_id,
  COALESCE(customer_id, 'C003') AS customer_id,
  customer_name,
  email,
  CASE WHEN country = 'IND' THEN 'India' ELSE country END AS country,
  CASE WHEN order_amount <= 0 THEN ABS(order_amount) ELSE order_amount END AS order_amount,
  UPPER(order_status) AS order_status,
  order_date,
  CASE
    WHEN TIMESTAMP_DIFF(loaded_at, order_date, MINUTE) > 60
      THEN TIMESTAMP_ADD(order_date, INTERVAL 10 MINUTE)
    ELSE loaded_at
  END AS loaded_at
FROM `YOUR_PROJECT_ID.dq_demo.customer_orders`;
Production warning: We are correcting values artificially only for a classroom demo. In a real system, do not invent missing IDs or change amounts without a trusted source/master record.

Create/repoint a scan to customer_orders_clean, run the same rules, and compare the results. The goal is to show the quality score moving from failure to pass after remediation.

Troubleshooting

Common practical issues

I cannot find “Dataplex” exactly as shown in older tutorials.

Google now documents the product as Knowledge Catalog (formerly Dataplex Universal Catalog). Search for data quality, data scans, or Knowledge Catalog in the console.

The timestamp expression errors.

Check that order_date and loaded_at were loaded as TIMESTAMP/DATETIME rather than plain STRING. If auto-detect chose STRING, recreate the table with an explicit schema or cast the values.

My non-null test passes unexpectedly.

CSV empty strings can sometimes be interpreted differently depending on schema/load settings. Preview the table and confirm whether the missing field is NULL or an empty string. If needed, use a custom condition that rejects both.

I cannot create/run a scan.

Check project billing, API enablement, IAM permissions, and supported source/location. Your organization may also restrict data scan creation.

The UI does not show the exact rule name in this tutorial.

Use the closest built-in rule (non-null, range, set, regex) or use a custom SQL expression. Console wording can change over time.

Interview perspective

Interview questions and model answers

1. What is data quality?

Data quality is the degree to which data is fit for its intended use. It is commonly evaluated through dimensions such as accuracy, completeness, timeliness, consistency, validity and uniqueness.

2. Difference between accuracy and completeness?

Completeness asks whether a required value exists. Accuracy asks whether the value is correct. A phone number may be present (complete) but belong to the wrong person (inaccurate).

3. Give a timeliness example.

A fraud dashboard that receives transactions three hours after they occurred may contain correct data but still fail its timeliness SLA.

4. What causes consistency problems?

Different naming conventions, casing, units, codes, date formats, duplicate master data and unsynchronized systems commonly cause consistency problems.

5. Can accuracy be checked only with NOT NULL?

No. NOT NULL measures presence, not correctness. Accuracy generally requires a trusted reference, valid range, business rule, or reconciliation with a source system.

6. How do thresholds work?

A threshold defines the acceptable percentage of records that must satisfy a rule. For critical identifiers you might require 100%; for less critical attributes the business may accept a lower threshold.

7. Why schedule data-quality scans?

Scheduled scans detect degradation over time and can support monitoring, alerting and SLAs instead of relying on one-time manual checks.

8. Is “India” vs “IND” always inconsistent?

Only if the data contract defines one canonical representation. If both are valid by design, they are not necessarily inconsistent. Quality rules must reflect business semantics.
