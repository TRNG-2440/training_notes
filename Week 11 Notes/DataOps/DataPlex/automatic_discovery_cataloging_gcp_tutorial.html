1. Learning Goal

By the end of this session, a trainee should be able to explain:

  • What automatic discovery means in a data platform.
  • What cataloging means and why it is different from storing data.
  • How the traditional spreadsheet/manual inventory approach works and why it breaks at scale.
  • How GCP Dataplex / Knowledge Catalog discovers and inventories metadata.
  • How BigQuery and Cloud Storage resources become searchable catalog entries.
  • How to perform a small practical demo in Google Cloud Console.
Trainer opening line: “Today we are not learning how to store data. We are learning how to automatically know what data exists, where it exists, and what it means.”

2. Small Story — The Supermarket Without Labels

Imagine a supermarket called FreshCart Mart. It has 10,000 products in a warehouse.

Initially, the warehouse manager keeps a notebook:

  • Rack A1 → Rice
  • Rack A2 → Sugar
  • Rack B1 → Soap
  • Rack C5 → Juice

For 100 products, this is manageable. But when the warehouse grows to 10,000 products:

  • new products arrive every day,
  • some products move to different racks,
  • some are renamed,
  • some are discontinued,
  • different employees maintain different Excel sheets.
Problem: The product exists physically, but employees cannot reliably find it because the inventory information is stale or incomplete.

Now map the story to data

Barcode scanner continuously updating inventoryAutomatic discovery and cataloging
Memory shortcut: A data catalog is like the searchable inventory system of a huge digital warehouse.

5. What Is Automatic Discovery and Cataloging?

5.1 Automatic Discovery

Automatic discovery means the platform scans or harvests metadata from supported data systems to identify data resources and their technical characteristics.

Think:

“What data exists?”
“Where is it?”
“What type of resource is it?”
“What is its schema?”
“What files/tables are present?”

5.2 Cataloging

Cataloging means registering that discovered metadata in a searchable metadata repository so users and systems can find and understand data assets.

BigQuery / GCS

Automatic

Metadata

One-line answer: Discovery finds the data; cataloging records information about the data so people can search and understand it.

Important: data is not copied into the catalog

The catalog primarily stores and manages metadata/context. Your underlying data can remain in BigQuery, Cloud Storage, or other supported systems.

6. What Metadata Can Be Discovered?

Metadata is “data about data.” Typical technical metadata includes:

Metadata TypeExample
Resource nameorders
Resource typeBigQuery table
LocationProject → dataset → table
Schemaorder_id INT64, customer_id STRING
Storage formatCSV / Parquet / BigQuery native table
Partition informationPartitioned by order_date
Creation/update metadataTimestamps
Business enrichmentDescription, glossary term, owner, aspects
Trainer distinction: Automatic discovery is strongest for technical metadata. Business meaning such as “this table is the approved revenue source” may still require enrichment, governance rules, glossary terms, or generated context.

7. How the Concept Works — Step by Step

Source data exists. Example: BigQuery tables and Cloud Storage files.
Discovery/harvesting reads metadata. The platform inspects supported resources or scans configured storage.
Metadata entries are created/updated. Resource names, schemas and other details become catalog metadata.
Metadata is indexed. It becomes searchable.
Users search instead of asking people. Analysts can search for “orders”, “customer”, “finance”, etc.
Governance enrichment can be added. Descriptions, classifications, aspects, glossary terms and ownership can improve trust.

11. Practical Demo — BigQuery + Knowledge Catalog

Demo use case: FreshCart has an orders table in BigQuery. We will create the table, confirm its technical metadata, then locate it from the catalog/search experience.

Prerequisites

  • Google Cloud project.
  • Billing/permissions appropriate for your organization.
  • BigQuery access.
  • Knowledge Catalog / Dataplex API enabled where required.
  • Permission to create and inspect metadata resources.

Part A — Create a BigQuery dataset

Open Google Cloud Console.
Search for BigQuery and open BigQuery Studio.
In Explorer, choose your project → Create dataset.
Dataset ID: freshcart_catalog_demo.
Choose a suitable location and create the dataset.

Part B — Create sample tables

Open the query editor and replace YOUR_PROJECT_ID below:

CREATE OR REPLACE TABLE
`YOUR_PROJECT_ID.freshcart_catalog_demo.orders` AS
SELECT 1001 AS order_id, 'C001' AS customer_id,
       DATE '2026-08-01' AS order_date,
       'Laptop' AS product, 65000 AS amount, 'PAID' AS status
UNION ALL
SELECT 1002, 'C002', DATE '2026-08-02', 'Mouse', 800, 'PAID'
UNION ALL
SELECT 1003, 'C003', DATE '2026-08-03', 'Keyboard', 1500, 'PENDING';

CREATE OR REPLACE TABLE
`YOUR_PROJECT_ID.freshcart_catalog_demo.customers` AS
SELECT 'C001' AS customer_id, 'Asha' AS customer_name, 'Coimbatore' AS city
UNION ALL
SELECT 'C002', 'Rahul', 'Chennai'
UNION ALL
SELECT 'C003', 'Meena', 'Bengaluru';

Part C — Inspect metadata in BigQuery first

Expand dataset freshcart_catalog_demo.
Open orders.
Observe the Schema: order_id, customer_id, order_date, product, amount, status.
Observe table details such as table ID, location and creation information.
Trainer message: “This information is metadata. We are not looking at the sales values yet; we are looking at information describing the table.”

Part D — Open Knowledge Catalog search

In Google Cloud Console search for Knowledge Catalog or the current Dataplex catalog/search experience.
Open the Search page.
Search for orders.
Filter by project/resource type if too many results appear.
Open the matching BigQuery table entry.
Review the available metadata such as resource type, location, schema and related context.
What proves cataloging? You created the table in BigQuery, then found its metadata through the catalog/search experience instead of maintaining a separate manual inventory.

14. What If the Data Changes?

Change the schema

Run:

ALTER TABLE
`YOUR_PROJECT_ID.freshcart_catalog_demo.orders`
ADD COLUMN sales_channel STRING;

Then reopen BigQuery schema and later check the catalog metadata after the platform has reflected the change.

Teaching point: Do not promise that every source change appears instantly in every catalog surface. Refresh/harvesting behavior depends on the source, integration and feature. The important concept is that metadata inventory is platform-managed rather than a human-maintained Excel sheet.

18. Interview Questions & Answers

1. What is automatic data discovery?

It is the automated identification and metadata harvesting/scanning of supported data resources so the platform can understand what data assets exist and their technical characteristics.

2. What is data cataloging?

Cataloging is storing and organizing metadata about data assets in a searchable repository so users can discover, understand and govern those assets.

3. Discovery vs cataloging?

Discovery finds or harvests metadata. Cataloging registers/indexes that metadata so it can be searched and managed.

4. Does a data catalog store all business data?

No. It mainly stores metadata/context about data resources. The underlying data remains in systems such as BigQuery or Cloud Storage.

5. Why is manual cataloging difficult?

Because people must continuously update documentation when resources, schemas and ownership change. At enterprise scale this becomes stale, incomplete and inconsistent.

6. Give a scenario for automatic discovery.

A retailer has hundreds of BigQuery datasets and Cloud Storage buckets. Instead of asking engineers to maintain spreadsheets, a catalog automatically inventories supported resources and makes their metadata searchable.

7. Is automatic discovery the same as data quality?

No. Discovery tells you what exists. Data quality determines whether values meet business rules.

8. Is automatic discovery the same as lineage?

No. Discovery inventories metadata; lineage shows upstream/downstream data movement and dependencies.

9. What is metadata?

Metadata is information describing data, such as table name, schema, location, type, descriptions, ownership and other context.

10. Why is a catalog useful for AI and analytics?

It provides organized enterprise context so analysts, applications and AI systems can locate and reason over governed data assets more reliably.
